# Farming Simulator 2025
## Блок `<i3dMappings>` в XML техники/оборудования

Сопоставление читаемых имён (id) узлам сцены `.i3d`[^i3d] по индексному пути.
Позволяет ссылаться на ноды[^node] по имени, а не по «сырому» пути `0>0|2|0`.

Источник: базовый загрузчик техники + `I3DUtil` (разрешение индекс→нода), `FS25`.

> Расположение в XML: `<i3dMappings>` — **дочерний элемент корня `<vehicle>`** (рядом с
> `<base>`), обычно в самом конце файла. В справочнике он в разделе `base` как общий блок.

---

## 1. Что это и зачем

В i3d каждый узел адресуется **индексным путём** вида `0>0|2|0`. Ссылаться на такие пути
напрямую по всему XML неудобно и хрупко (при изменении модели пути «съезжают»).
`<i3dMappings>` задаёт **алиасы**: каждому узлу — понятное имя (`id`), и дальше по всему
XML используется это имя.

- Все атрибуты-ссылки на ноды (`node`, `linkNode`, `startNode`, `refNode`, `rootNode`,
  `effectNode` и т.п.) принимают **либо сырой индексный путь, либо `id`** из маппинга.
- При правке модели достаточно обновить путь **в одном месте** — в `<i3dMappings>`, а все
  ссылки по имени продолжают работать.

---

## 2. Атрибуты `<i3dMapping>`

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | STRING | Читаемое имя-алиас (обычно совпадает с именем ноды в i3d). По нему ссылаются из XML. |
| `node` | STRING | Индексный путь узла в сцене (см. формат ниже). |

```xml
<i3dMappings>
    <i3dMapping id="workAreaStart" node="0>0|2|0"/>
</i3dMappings>
```

---

## 3. Формат индексного пути (`node`)

Общий вид: `A>B|C|D`

- **`A`** (до `>`) — индекс загруженного i3d-файла. У мода с одной моделью это `0`
  (основной `.i3d`); дополнительно подгруженные i3d получают следующие индексы.
- **`B|C|D`** (после `>`) — путь дочерних индексов от корня файла, разделённых `|`.
  Отсчёт **с нуля**, в порядке дерева сцены.

Разбор примеров:

| Путь | Что это |
|---|---|
| `0>` | корневой узел файла 0 |
| `0>0` | первый дочерний узел корня |
| `0>0|1` | корень → ребёнок 0 → ребёнок 1 |
| `0>0|2|0` | корень → ребёнок 0 → ребёнок 2 → ребёнок 0 |

---

## 4. Как ссылки используют маппинг

Везде, где атрибут ожидает узел, можно писать `id` из маппинга:

```xml
<i3dMappings>
    <i3dMapping id="reelArm"        node="0>0|1|2"/>
    <i3dMapping id="workAreaStart"  node="0>0|2|0"/>
    <i3dMapping id="workAreaWidth"  node="0>0|2|1"/>
    <i3dMapping id="workAreaHeight" node="0>0|2|2"/>
</i3dMappings>

<!-- дальше по XML ссылки идут по имени, а не по пути -->
<workAreas>
    <workArea type="cutter" functionName="processCutterArea">
        <area startNode="workAreaStart" widthNode="workAreaWidth" heightNode="workAreaHeight"/>
    </workArea>
</workAreas>

<cylindered>
    <movingTool node="reelArm"/>
</cylindered>
```

Загрузчик разрешает имя в реальный узел через `i3dMappings` (индекс→объект). Если имени
в маппинге нет, значение трактуется как сырой индексный путь.

## 5. Автоматическое создание маппинга

Ручной подсчёт путей подвержен ошибкам; для автоматической генерации применяются инструменты:

- **Встроенная панель GIANTS Editor 10 «I3D Mappings».** Выделяешь нужные ноды в дереве
  сцены, в разделе I3D Mappings жмёшь **GENERATE** (создать) или **UPDATE** (обновить) —
  редактор пишет/актуализирует блок `<i3dMapping>` в XML. Часть [GIANTS Modding Tools для FS25](https://forum.giants-software.com/viewtopic.php?t=210005).
- **Скрипт [GtX-Andy/GE10_CreateI3DMappings](https://github.com/GtX-Andy/GE10_CreateI3DMappings)** —
  выводит теги `<i3dMapping/>` для всех выделенных нод (есть альтернативный v2-синтаксис пути).
- **[w33zl/GE-PowerTools](https://github.com/w33zl/GE-PowerTools)** — набор editor-скриптов,
  включая генерацию i3d-маппингов.

`id` по умолчанию берётся из **имени ноды** в i3d, поэтому давай нодам осмысленные имена
до генерации.

---

## 6. Создание вручную

1. В GIANTS Editor выдели узел — его **индексный путь** виден по положению в дереве сцены
   (порядковые номера детей от корня, с нуля).
2. Составь путь `0>...|...` от корня файла до узла.
3. Добавь строку:

   ```xml
   <i3dMapping id="myNode" node="0>0|3|1"/>
   ```
4. Ссылайся по `id` из остального XML.

Ручной способ уместен для единичных правок; для полного блока быстрее и надёжнее
инструменты из п.5.

---

## 7. Типичные ошибки

- **Путь не совпадает с деревом** (после перестройки модели индексы «съехали») — перегенерируй
  маппинг (UPDATE), не правь пути вручную по одному.
- **Ссылка на несуществующий `id`** — значение уйдёт в трактовку как сырой путь и,
  скорее всего, не разрешится. Проверь совпадение имён.
- **Неуникальные `id`** — имена в маппинге должны быть уникальны.
- **Забыт индекс файла** (`0>` перед путём) — путь должен начинаться с индекса i3d-файла.
