# Farming Simulator 2025
## Элемент `<specializations>`

```xml
<specializations>
    <specialization name="script"
                    className="Script"
                    filename="scripts/script.lua"/>
</specializations>
```

Регистрирует **кастомные спецификации** техники — Lua-скрипты, добавляющие технике новое
поведение. Блок только объявляет спеку движку; чтобы она заработала, её отдельно добавляют к типу
техники (см. раздел 6). Внутренности самого скрипта — это скриптинг, вне объёма данного справочника.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

Спецификация (specialization) — модуль поведения техники в FS. `<specializations>` перечисляет
собственные спеки мода: даёт каждой имя, указывает её класс и файл. При загрузке мода движок
регистрирует эти спеки и делает их доступными для добавления к типам техники.

---

## 2. Атрибуты `<specialization>`

Все три обязательны.

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да | Имя спецификации. Регистрируется с префиксом мода: `<modName>.<name>`. |
| `className` | STRING | да | Имя глобальной Lua-таблицы (класса), реализующей спеку. |
| `filename` | STRING | да | Путь к `.lua`-файлу спеки, относительно корня мода. |

`<specializations>` необязателен (`minOccurs="0"`), один; `<specialization>` внутри может быть
несколько.

---

## 3. Что задаёт каждый атрибут

- **`name`** — короткое имя спеки. Движок регистрирует её под именем с префиксом мода:
  `<modName>.<name>`. По этому имени спеку добавляют к типам техники, а внутри техники её данные
  лежат в таблице `self["spec_<modName>.<name>"]`.
- **`className`** — имя **глобальной таблицы** Lua, объявленной в файле спеки (в примере файл
  создаёт `Script = {}`). Через неё движок находит функции спеки.
- **`filename`** — путь к файлу скрипта от корня мода (`scripts/script.lua`). Файл загружается при
  регистрации.

---

## 4. Что происходит при загрузке

При загрузке мода движок для каждого `<specialization>`:

1. Загружает файл `filename` (в нём должна появиться глобальная таблица `className`).
2. Регистрирует спеку под именем `<modName>.<name>` в менеджере спецификаций.

После этого спека **доступна**, но ещё ни к какой технике не привязана.

---

## 5. Что содержит класс спеки

Таблица `className` реализует стандартный интерфейс спецификации FS (детали — уже область
скриптинга): проверку предпосылок (`prerequisitesPresent`), регистрацию слушателей событий
(`registerEventListeners`), при необходимости — регистрацию функций и перезаписей
(`registerFunctions`, `registerOverwrittenFunctions`), инициализацию (`initSpecialization`), и сами
обработчики (`onLoad`, `onUpdate`, `onDelete` и т.п.). Данные экземпляра спека хранит в
`self["spec_<modName>.<name>"]`.

---

## 6. Регистрация ≠ использование

Объявление в `<specializations>` только **регистрирует** спеку. Чтобы она реально применилась к
технике, её надо **добавить к типу техники** одним из способов:

- **Декларативно** — объявить кастомный тип техники в `<vehicleTypes>`, перечислив в нём эту
  спеку (по имени `<modName>.<name>`), и указывать этот тип в XML техники (`<vehicle type="...">`).
- **Кодом** — прикрепить спеку к существующим типам через хук менеджера типов
  (`TypeManager.validateTypes` → `typeManager:addSpecialization(typeName, "<modName>.<name>")`).

Если этого не сделать, скрипт будет зарегистрирован, но не выполнится ни на одной технике.

---

## 7. Примеры

Одна спека:

```xml
<specializations>
    <specialization name="script" className="Script" filename="scripts/script.lua"/>
</specializations>
```

Несколько спек:

```xml
<specializations>
    <specialization name="spillOnRollover" className="SpillOnRollover" filename="scripts/SpillOnRollover.lua"/>
    <specialization name="spillDust"       className="SpillDust"       filename="scripts/SpillDust.lua"/>
</specializations>
```

---

## 8. Типичные ошибки

- **`className` не совпадает** с именем глобальной таблицы в файле — движок не найдёт функции спеки.
- **Неверный `filename`** (путь/регистр) — файл не загрузится.
- **Забыли добавить спеку к типу техники** (раздел 6) — спека зарегистрирована, но не работает.
- **Путаница `name` и `className`** — `name` это имя спеки (для привязки к типам), `className` это
  Lua-таблица.

---

## 9. Примечания

- Имя спеки всегда неймспейсится модом: `<modName>.<name>` — так исключаются конфликты между модами.
- Данные спеки на технике — в `self["spec_<modName>.<name>"]`.
- Внутренняя реализация класса спеки — скриптинг Lua; данный справочник описывает только XML-объявление.
