# Farming Simulator 2025
## Элемент `<inputBinding>`

```xml
<inputBinding>
    <actionBinding action="BMP_DISEASE_MINIMAP_TOGGLE">
        <binding device="KB_MOUSE_DEFAULT" input="KEY_lalt KEY_backslash" index="1"/>
    </actionBinding>
</inputBinding>
```

Задаёт **привязки по умолчанию** для действий ввода — какие клавиши/кнопки изначально назначены на
действия. Пара к [`<actions>`](actions.md): там действие объявляется, здесь ему даётся стартовая
клавиша. Привязка из мода — только **дефолт первого запуска**; если игрок переназначил или уже есть
сохранённая привязка, она имеет приоритет (раздел 6).

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

`<inputBinding>` перечисляет `<actionBinding>`, каждый — для одного действия (по имени), и внутри —
одну или несколько `<binding>` (клавиша/кнопка/ось на конкретном устройстве). При загрузке эти привязки
применяются как значения по умолчанию к действиям (базовым и модовым) — уже после чтения сохранённого
конфига игрока, поэтому не затирают его выбор.

---

## 2. Структура

```
<inputBinding>
    <actionBinding action="ИМЯ_ДЕЙСТВИЯ">
        <binding device="..." input="..."/>
    </actionBinding>
</inputBinding>
```

- **`<actionBinding action="...">`** — привязки для одного действия. `action` — имя действия из
  [`<actions>`](actions.md) **или базового** действия игры (имена глобальны). Действие резолвится в общей
  карте имён; если такого имени нет — блок молча пропускается.
- **`<binding>`** — конкретная привязка. Несколько `<binding>` = альтернативные привязки/разные
  устройства.

---

## 3. Атрибуты `<binding>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `input` | STRING[^string] | нет | Токен(ы) ввода. Через пробел — комбо: последний токен основной, предыдущие — модификаторы. Пусто `""` — намеренно без привязки. |
| `device` | STRING | нет | Устройство: `KB_MOUSE_DEFAULT`, `GAMEPAD_DEFAULT` (или конкретное `0_XINPUT_GAMEPAD`), `WHEEL_DEFAULT` и т.п. Пусто `""` — без устройства (не привязано). |
| `index` | INT[^int] | нет | Слот альтернативной привязки. По умолчанию `-1`. Клав/мышь — до 3 слотов, геймпад — до 2. |
| `axisComponent` | STRING | нет | `+` (по умолчанию) или `-` — какая половина `FULL`-оси. |
| `inputComponent` | STRING | нет | `+` (по умолчанию) или `-` — полярность аналогового сигнала. Хвостовой `-` у токена задаёт `-`. |
| `neutralInput` | INT | нет | Нейтральное (покойное) значение аналоговой оси. По умолчанию `0`. |

---

## 4. Токены `input` и `device`

**`input`** разбирается по пробелам. Последний токен — основной ввод, предшествующие — модификаторы
(комбо). Токены — имена из глобальной таблицы ввода движка:

- Клавиатура: `KEY_*` — `KEY_a`, `KEY_lshift`, `KEY_lctrl`, `KEY_lalt`, `KEY_insert`, `KEY_backslash`,
  цифровой блок `KEY_KP_4`, функциональные `KEY_f12`.
- Мышь: `MOUSE_BUTTON_LEFT` / `RIGHT` / `MIDDLE` / `WHEEL_UP` / `WHEEL_DOWN` / `X1` / `X2` и оси мыши.
- Геймпад: кнопки `BUTTON_n`, оси `AXIS_n` (хвостовой `+`/`-` задаёт направление).
- Комбо: `input="KEY_lctrl KEY_lshift KEY_a"` — три токена в одном атрибуте.
- Пусто: `input=""` (обычно вместе с `device=""`) — действие объявлено, но по умолчанию не привязано.

**`device`** — идентификатор устройства. Символические значения по умолчанию (`KB_MOUSE_DEFAULT`,
`GAMEPAD_DEFAULT`, …) при загрузке сопоставляются с реально подключённым устройством нужной категории.
Модовые дефолты обычно пишут `device="KB_MOUSE_DEFAULT"` (клав/мышь) или `GAMEPAD_DEFAULT` (геймпад).

---

## 5. Аналоговые оси

Для аналоговых привязок (геймпад/руль): `axisComponent` выбирает половину `FULL`-оси действия (`+`/`-`),
`inputComponent` — полярность самого сигнала (`+`/`-`; хвостовой `-` у токена, например `AXIS_2-`,
задаёт отрицательную полярность), `neutralInput` — значение оси в покое (для триггеров, «отдыхающих» в
одном крайнем положении). Для обычных клавиш/кнопок эти три атрибута не нужны.

---

## 6. Дефолт против сохранённого

Порядок загрузки: базовые действия → действия модов → **сохранённые привязки игрока**
(`config/inputBinding.xml`) → **дефолты из `<inputBinding>` модов** (применяются последними). Модовый
дефолт ставится **только если у действия ещё нет известной/сохранённой привязки**. Как только игрок
переназначил клавишу (или привязка сохранена), его выбор побеждает над модовым дефолтом.

Модовые дефолты грузятся с подавлением предупреждений о дубликатах. Конфликт/занятый слот/превышение
числа альтернатив — не фатальны: привязка просто игнорируется.

## 7. Примеры

Своё действие с комбо-привязкой (реальный мод FS25_CropDiseases_BMP):

```xml
<inputBinding>
    <actionBinding action="BMP_DISEASE_MINIMAP_TOGGLE">
        <binding device="KB_MOUSE_DEFAULT" input="KEY_lalt KEY_backslash" index="1"/>
    </actionBinding>
</inputBinding>
```

Комбо на клав/мышь и параллельная привязка на геймпаде:

```xml
<actionBinding action="ADToggleHud">
    <binding device="KB_MOUSE_DEFAULT" input="KEY_lalt KEY_KP_0"/>
    <binding device="0_XINPUT_GAMEPAD" input="BUTTON_5 BUTTON_17"/>
</actionBinding>
```

Одиночная клавиша и мышь:

```xml
<actionBinding action="CP_START_STOP">
    <binding device="KB_MOUSE_DEFAULT" input="KEY_lctrl KEY_h"/>
</actionBinding>
<actionBinding action="CP_TOGGLE_MOUSE">
    <binding device="KB_MOUSE_DEFAULT" input="MOUSE_BUTTON_RIGHT"/>
</actionBinding>
```

Намеренно без привязки по умолчанию (игрок назначит сам):

```xml
<actionBinding action="CP_CLEAR_COURSE">
    <binding device="" input=""/>
</actionBinding>
```

## 8. Типичные ошибки

- **`action` не объявлен** (ни в [`<actions>`](actions.md), ни базовый) — `actionBinding` молча
  пропускается.
- **Неверный токен `input`/`device`** — токена нет в таблице ввода: привязка не применится.
- **Комбо через дефис/запятую** — токены комбо разделяются **пробелом** в одном атрибуте `input`.
- **Ожидание, что дефолт перебьёт выбор игрока** — нет: сохранённая/переназначенная привязка приоритетнее.
- **Регистр токенов/модификаторов** — использовать точные имена (`KEY_lshift`, не `KEY_LSHIFT`).

---

## 9. Примечания

- Привязка из мода — дефолт первого запуска; далее приоритет у конфига игрока.
- `action` ссылается на глобальное имя действия (своё или базовое); имена не неймспейсятся модом.
- `input` — токены через пробел (последний основной, прочие модификаторы); `device` — символическое
  устройство по умолчанию, резолвится в подключённое.
- Аналоговые атрибуты (`axisComponent`/`inputComponent`/`neutralInput`) нужны только для осей.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры.
