# Farming Simulator 2025
## Элемент `<brands>`

```xml
<brands>
    <brand name="FARMERTOOLS" title="Farmer Tools" image="store/brand_FarmerTools.dds"/>
</brands>
```

Регистрирует **бренды (производителей)** — марку, которая показывается на товаре в магазине. Каждый
`<brand>` задаёт имя-идентификатор, отображаемое название, логотип и выравнивание логотипа. На бренд
затем ссылается товар полем `<storeData><brand>`.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.
>
> В отличие от [`<storeCategories>`](store-categories.md), `<brands>` читается у **всех** модов, не
> только у DLC.

---

## 1. Что это

У каждого товара магазина есть бренд-производитель (Lizard, John Deere, Horsch и т.п.). Игра держит
набор базовых брендов; `<brands>` позволяет моду **добавить свой бренд** в общий реестр, а товары
ссылаются на него по имени. Логотип бренда виден в карточке магазина.

Реестр брендов общий и глобальный: имя не неймспейсится по имени мода (как у `jointTypes`), поэтому его
стоит делать уникальным. Базовые бренды заданы в `dataS/brands.xml`.

---

## 2. Атрибуты `<brand>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да (практически) | Имя-идентификатор. Только **заглавные буквы и подчёркивания**; приводится к верхнему регистру. Становится ключом `Brand.<NAME>`. По нему ссылаются в `<storeData><brand>`. |
| `title` | STRING | да (практически) | Отображаемое название бренда в UI. `$l10n_<ключ>` резолвится через локализацию мода; иначе — обычный текст. |
| `image` | STRING | да (практически) | Логотип бренда. Путь относительно корня мода. На практике `.dds`. |
| `imageOffset` | FLOAT[^float] | нет | Доля `[0..1]` прозрачных краёв логотипа для выравнивания в UI. По умолчанию `0`. |

`<brands>` необязателен (`minOccurs="0"`), один; `<brand>` внутри может быть несколько. Схема не помечает
атрибуты обязательными, но при пустых `name`/`title`/`image` регистрация бренда прерывается с
предупреждением.

Иконку для «обзора магазина» (`imageShopOverview`) из modDesc задать нельзя — движок передаёт её как
`nil`; это поле только у базовых брендов.

---

## 3. Регистрация

При загрузке мода движок читает `modDesc.brands.brand` (у **всех** модов, без гейта DLC — в отличие от
`<storeCategories>`) и вызывает `g_brandManager:addBrand(name, title, image, modDir, …, imageOffset)`.

- **`name`** приводится к верхнему регистру и проверяется на валидность (только заглавные и `_`).
  Невалидное имя → предупреждение, бренд не регистрируется.
- **Глобально, без префикса мода.** Имя попадает в общий реестр (`Brand.<NAME>`), видимый всем модам и
  базовой игре.
- **Дубликат — первый побеждает.** Если бренд с таким именем уже есть, повторная регистрация молча
  игнорируется. Свой бренд **не может** переопределить базовый бренд с тем же именем.

---

## 4. Как товар ссылается на бренд

В файле предмета: `<storeData><brand>ИМЯ</brand>` (см. [storeItems](store-items.md)). Имя резолвится к
индексу бренда (регистр не важен). Пустое или неизвестное имя → откат к базовому бренду `LIZARD`
(значение по умолчанию поля `storeData.brand` в схеме — тоже `LIZARD`).

Товар может **переопределить логотип на своём уровне**, не трогая сам бренд:

| Поле `<storeData>` | Назначение |
|---|---|
| `brand` | Имя бренда (текст элемента). |
| `brand#customIcon` | Свой логотип для карточки конфигурации (путь резолвится относительно предмета). |
| `brand#imageOffset` | Смещение своего логотипа. |

---

## 5. Базовые бренды

Базовые бренды заданы в `dataS/brands.xml` (в открытые исходники не входит, поэтому полный список имён
первоисточником не подтверждается). Из кода достоверны имена `LIZARD` (запасной бренд) и `HORSCH`
(пример в документации движка). Остальные — реальные производители (например `CASEIH`, `FENDT`,
`JOHNDEERE`, `KRONE` и др.) — внешнее знание, в дампах исходников их нет.

Глобальная таблица `Brand` отображает имя → индекс и пополняется по мере регистрации брендов
(базовых и модовых).

---

## 6. Примеры

Свой бренд (реальный мод FS25_DigitalDisplay) и ссылка на него в товаре:

```xml
<!-- modDesc.xml -->
<brands>
    <brand name="FARMERTOOLS" title="Farmer Tools" image="store/brand_FarmerTools.dds"/>
</brands>
```

```xml
<!-- в файле предмета -->
<storeData>
    ...
    <brand>FARMERTOOLS</brand>
    ...
</storeData>
```

Бренд с логотипом в подпапке (реальный мод FS25_UsedPlus):

```xml
<brands>
    <brand name="GMC" title="GMC" image="gui/icons/brand_gmc.dds"/>
</brands>
```

## 7. Типичные ошибки

- **Строчные буквы/дефисы/цифры в `name`** — невалидное индекс-имя (нужны только заглавные и `_`); бренд
  не зарегистрируется.
- **Пустой `name`/`title`/`image`** — предупреждение, бренд отброшен.
- **Расчёт на переопределение базового бренда** — дубликат имени игнорируется (первый побеждает).
- **Ссылка на несуществующий бренд в `storeData`** — откат к `LIZARD` (логотип будет не тот).
- **Логотип не `.dds`** — формально не проверяется, но `.dds` — рабочая практика; иные форматы могут
  не отобразиться.
- **Ожидание, что `<brands>` только для DLC** — нет, читается у всех модов (в отличие от
  `<storeCategories>`).

---

## 8. Примечания

- Реестр брендов общий и глобальный; имя не неймспейсится модом — стоит делать его уникальным.
- `name` — только заглавные и `_`, становится ключом `Brand.<NAME>`; резолвится в индекс при ссылке из
  `storeData.brand`.
- `title` — `$l10n_`-ключ или текст; `image` — путь в моде; `imageOffset` — доля прозрачных краёв `[0..1]`.
- Запасной бренд при неизвестном имени — `LIZARD`.
- Товар может переопределить логотип полями `storeData.brand#customIcon`/`#imageOffset`, не меняя бренд.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры. Полный список
  базовых имён из `dataS/brands.xml` в исходники не входит.
