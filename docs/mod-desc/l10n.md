# Farming Simulator 2025
## Элемент `<l10n>`

```xml
<l10n filenamePrefix="localization/l10n"/>
```

Локализация мода: набор переводимых текстов (ключ → строка на разных языках). Тексты задаются
двумя способами — внешними файлами (`filenamePrefix`) или инлайн прямо в `modDesc`. Элемент
необязателен.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.
>
> Внутренняя структура отдельных файлов `l10n_<код>.xml` рассматривается в отдельной статье; здесь —
> сам элемент `<l10n>` и два способа объявления переводов.

---

## 1. Что это

`<l10n>` объявляет строки перевода мода. Каждой строке даётся **ключ**, по которому её потом
подставляют в XML (`$l10n_<ключ>`) или получают в Lua (`g_i18n:getText("<ключ>")`). Один и тот же
ключ хранит варианты на разных языках; игрок видит текст на языке игры.

Есть два способа наполнить локализацию:

- **Внешние файлы** — атрибут `filenamePrefix` (раздел 2).
- **Инлайн** — дочерние `<text>` прямо в `modDesc` (раздел 3).

---

## 2. Внешние файлы — `filenamePrefix`

```xml
<l10n filenamePrefix="localization/l10n"/>
```

| Атрибут | Тип | Описание |
|---|---|---|
| `filenamePrefix` | STRING[^string] | Префикс пути к файлам перевода, относительно корня мода. |

Как резолвится: движок добавляет к префиксу суффикс `_<код>.xml`. То есть
`filenamePrefix="localization/l10n"` → файлы `localization/l10n_en.xml`, `localization/l10n_ru.xml`
и т.д. Базовое имя произвольно (например `l10n/l10n`, `modDesc_l10n`), **фиксирован только суффикс**
`_<код>.xml`, где `<код>` — код языка (тот же набор, что у `<title>`/`<description>` — см. [title](title.md)).

Каждый файл — **один язык** (язык закодирован в имени файла). Формат содержимого файла — одна из
двух форм (по документации схемы):

- Форма A (используется всеми реальными модами): `<l10n><texts><text name="ключ" text="значение"/></texts></l10n>`
- Форма B (описана в схеме, но в живых модах не встречается): `<l10n><elements><e k="ключ" v="значение"/></elements></l10n>`

Подробный разбор внутреннего формата файла — в отдельной статье.

Когда удобно: много строк и/или командный перевод (каждый язык — свой файл; добавить язык = просто
положить новый `l10n_<код>.xml`, не трогая `modDesc`).

---

## 3. Инлайн-переводы в modDesc

```xml
<l10n>
    <text name="variant01">
        <en>Option 1</en>
        <ru>Вариант 1</ru>
        <de>Option 1</de>
    </text>
    <text name="option_wheels">
        <en>Selection of support wheels</en>
        <ru>Выбор опорных колёс</ru>
    </text>
</l10n>
```

Здесь переводы лежат прямо в `modDesc`. Каждый `<text>` имеет атрибут `name` (ключ) и языковые
дочерние элементы (`<en>`, `<ru>`, … — тот же закрытый набор из 27 кодов, что у `<title>`). Тексты
попадают в локализацию мода так же, как из внешних файлов, и используются идентично.

Отличие от внешней Формы A: инлайн задаёт язык **дочерними элементами** внутри одного `<text>`,
а внешний файл — атрибутом `text=` в отдельном файле на язык.

Когда удобно: немного строк, один-два языка, которые не отдаются на перевод (компактно, всё в modDesc).

---

## 4. Инлайн или внешние файлы

Это два **альтернативных** способа; на практике мод использует один. Схема структурно допускает
одновременно и `filenamePrefix`, и инлайн-`<text>`, но правило слияния/приоритета из схемы и движка
неизвестно — **смешивать не следует**.

- **Инлайн** — мало строк, компактно, всё в `modDesc`.
- **Внешние файлы** — много строк, перевод по языкам/командой, `modDesc` остаётся коротким.

---

## 5. Как использовать ключи

- **В XML** (GUI, конфиги техники, магазин) — литерал `$l10n_<ключ>` в текстовом атрибуте:
  ```xml
  text="$l10n_spill_enabled"
  texts="$l10n_spill_mode_monotone|$l10n_spill_mode_twophase"
  ```
  Движок подставляет перевод там, где парсер ожидает `$l10n_`. Подстановка работает в большинстве
  текстовых полей, но **не универсальна**: есть атрибуты, где она не срабатывает (известный пример —
  `sellingStation#stationName`). Каждое новое место стоит проверять.
- **В Lua** — `g_i18n:getText("<ключ>")` возвращает строку во время выполнения.

`$l10n_` — удобство на стороне XML; `getText` — API на стороне Lua.

---

## 6. Тексты мода приватны (неймспейсинг)

Локализация мода **видна только самому моду** (его среде Lua) — так сделано, чтобы ключи разных
модов не конфликтовали. Код базовой игры (например `InGameMenuSettingsFrame`) работает в базовой
среде и **не видит** текстов мода.

Обход для базового контекста: продублировать ключ с префиксом `global_` и при загрузке скопировать
такие ключи в базовую таблицу текстов (`baseEnv.g_i18n:setText(name:sub(8), value)`, где `baseEnv`
получают через `getmetatable(_G).__index`). Встроенного API для чтения текстов чужого мода/базы нет.

---

## 7. Языки и фолбэк

- Коды языков — тот же закрытый набор, что у `<title>`/`<description>` (см. [title](title.md));
  суффикс файла = код языка.
- **`en` обязателен** и служит значением по умолчанию (подтверждено GIANTS). Если для текущего
  языка нет файла/ключа — берётся `en`.
- Если нет и `en` — ключ не резолвится: показывается заглушка (например литерал `$l10n_<ключ>`),
  в лог пишется предупреждение вида `missing <ключ> in l10n_<язык>.xml`.
- Вторичный фолбэк на `de` после `en` упоминается сообществом, но первоисточником GIANTS не
  подтверждён; надёжен только `en`.

---

## 8. Примеры

Вынос во внешние файлы:

```xml
<!-- modDesc.xml -->
<l10n filenamePrefix="localization/l10n"/>
<!-- файлы: localization/l10n_en.xml, localization/l10n_ru.xml, ... -->
```

Инлайн (немного строк):

```xml
<l10n>
    <text name="spill_enabled">
        <en>Spill on rollover</en>
        <ru>Высыпание при опрокидывании</ru>
    </text>
</l10n>
```

Использование ключа в GUI-XML:

```xml
<Text text="$l10n_spill_enabled"/>
```

---

## 9. Типичные ошибки

- **Нет `en`** — для языков без своего перевода текст не покажется (нет фолбэка).
- **Ожидание, что `$l10n_` работает везде** — есть атрибуты, где подстановки нет.
- **Смешивание** `filenamePrefix` и инлайн-`<text>` — правило приоритета не определено.
- **Неверный суффикс файла** — должен быть строго `_<код>.xml` (не `.en.xml`, не `_english.xml`).

---

## 10. Примечания

- `<l10n>` необязателен; нужен, когда моду требуются собственные переводимые строки.
- Внешний файл `modDesc.xsd` не валидирует (схема описывает только инлайн-форму); форматы внешних
  файлов заданы прозой в документации атрибута `filenamePrefix`.
- Из двух внешних форм на практике используется только Форма A (`texts.text#name/#text`); Форма B
  (`elements.e#k/#v`) документирована, но в живых модах не наблюдается.
- Что при загрузке читается только файл активного языка плюс `en` (а не все файлы сразу) — вывод
  по архитектуре движка; первоисточником не подтверждён.
