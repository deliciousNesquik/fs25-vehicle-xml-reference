# Farming Simulator 2025
## Элемент `<missionVehicles>`

```xml
<missionVehicles filename="xml/missionVehicles.xml"/>
```

Подключает **пул техники для контрактов** (полевые миссии: уборка, посев, вспашка, покос+тюкование и
т.п.). В modDesc это только **ссылка на внешний файл**: единственный атрибут `filename` указывает на XML,
где по типам миссий и размерам поля перечислены наборы техники, которую игра **выдаёт в аренду** на время
контракта.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

Когда игрок берёт контракт, игра одалживает ему технику из пула для данного типа миссии и размера поля.
Игра держит базовый пул (задаётся картой); `<missionVehicles filename="...">` **добавляет** свои наборы.
Наборы регистрируются в общем пуле (`g_missionManager`); при генерации контракта выбирается случайный
подходящий набор.

Читается у **всех** модов (не только DLC); разбор отложен: сначала грузится файл **карты**
(`map.missionVehicles#filename`), затем **дополняются** файлы модов. Механизм чисто **аддитивный** —
заменить/удалить базовые наборы нельзя (раздел 6).

---

## 2. Атрибут `<missionVehicles>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `filename` | STRING[^string] | да (практически) | Путь к внешнему XML с пулом техники. Относительно корня мода; `$data/…` — от корня игры. |

Наборов инлайн в modDesc нет — только ссылка на файл.

---

## 3. Внешний файл

Корень внешнего файла — `<missionVehicles>`. Иерархия: `<mission>` → `<group>` → `<vehicle>`.

**`<mission type="...">`** — группа наборов для одного типа миссии. `type` **обязателен** и должен
совпадать с зарегистрированным типом миссии (раздел 4); в FS25 неизвестный тип пропускается с ошибкой.

**`<group>`** — один набор техники:

| Атрибут | По умолчанию | Описание |
|---|---|---|
| `size` | `medium` | Размер поля: `small` / `medium` / `large` (раздел 4). |
| `rewardScale` | `1` | Множитель вознаграждения для набора. |
| `variant` | — | Вариант набора (под конкретную культуру/продукт, раздел 4). |

**`<vehicle filename="...">`** — единица техники в наборе. `filename` **обязателен** и должен резолвиться
в **товар магазина** (`getItemByXMLFilename`) — иначе запись пропускается с ошибкой. Путь относительно
базовой директории файла (мод/карта); `$data/…` — базовая техника игры.

**`<configuration name="..." id="...">`** — дочерние у `<vehicle>`: конфигурации выдаваемой техники
(например цвет/навеска), пары `name`→`id`.

Других полей (`configFilename`, `fillType`, `maxFieldPercentage`, `requireFarmland` и т.п.) движок **не
читает** — только перечисленное. Выбор нужного варианта/культуры делает код миссии.

---

## 4. Типы миссий, размеры поля, варианты

**Типы миссий (`mission#type`), базовые:** `harvest`, `sow`, `plow`, `cultivate`, `fertilize`, `spray`,
`weed`, `mow_bale`, `transport`. Покос и тюкование — **единый** тип `mow_bale` (отдельных `mow`/`bale`
нет). FS25 добавляет сбор камней (`stonePick`).

**Размер поля** (`size`/`fieldSize`) вычисляется из площади поля: `small` (< 1.5 га), `medium`
(1.5–5 га), `large` (> 5 га). Значение по умолчанию — `medium`.

**`variant`** позволяет держать наборы под конкретную культуру/продукт, чтобы выдавалась правильная
жатка/орудие. Код миссии вычисляет нужный вариант: например уборка/посев — `MAIZE`, `SUGARBEET`,
`POTATO`, `COTTON`, `SUGARCANE`, `CARROT` (иначе — зерно, вариант не задан); `mow_bale` — `SILAGE` или
`HAY`. Набор без `variant` выбирается только когда миссия запрашивает «без варианта».

---

## 5. Как контракт использует пул

- При генерации: `getRandomVehicleGroup(type, size, variant)` берёт список наборов
  `[тип][размер]`, фильтрует по варианту и выбирает **случайный**.
- Техника набора **выдаётся в аренду** (спавнится как имущество миссии со случайным износом); по
  завершении/отказе контракта — удаляется.
- Экономика: вознаграждение считается по площади поля + возмещение; аренда техники стоит отдельно.
  `rewardScale` — задуманный множитель вознаграждения набора.

---

## 6. Только добавление (без замены)

Пул `missionVehicles` — единая глобальная структура `[тип][размер] → список наборов`, не неймспейсится по
моду. Все источники (карта + все моды) **сливаются** в неё; выбор — случайный по объединённому списку.
Механизма overwrite/append/replace **нет** — мод может только **дополнить** пул, но не убрать/переопределить
базовые или картовые наборы.

---

## 7. Пример

Подключение в modDesc:

```xml
<missionVehicles filename="xml/missionVehicles.xml"/>
```

Внешний файл — наборы по типам и размерам (техника — товары магазина, здесь базовые через `$data`):

```xml
<missionVehicles>
    <mission type="harvest">
        <group size="small">
            <vehicle filename="$data/vehicles/.../combine.xml">
                <configuration name="design" id="2"/>
            </vehicle>
            <vehicle filename="$data/vehicles/.../header.xml"/>
        </group>
        <group size="large" variant="MAIZE">
            <vehicle filename="$data/vehicles/.../bigCombine.xml"/>
            <vehicle filename="$data/vehicles/.../maizeHeader.xml"/>
        </group>
    </mission>

    <mission type="mow_bale">
        <group size="medium" variant="HAY">
            <vehicle filename="$data/vehicles/.../mower.xml"/>
            <vehicle filename="$data/vehicles/.../baler.xml"/>
        </group>
    </mission>
</missionVehicles>
```

## 8. Типичные ошибки

- **Инлайн-наборы в modDesc** — нельзя; `<missionVehicles>` только `filename`, наборы в отдельном файле.
- **`mission#type` не совпадает** с зарегистрированным типом — в FS25 пропускается с ошибкой; используйте
  точные имена (`harvest`, `mow_bale`, …).
- **`vehicle#filename` не товар магазина** — запись пропускается (техника должна иметь `<storeData>` и быть
  зарегистрирована как store item).
- **Отдельные типы `mow`/`bale`** — их нет; покос+тюкование это `mow_bale`.
- **Ожидание замены базового пула** — нельзя, только добавление; лишние наборы просто расширяют случайную
  выборку.
- **Атрибут размера** — используется `size`.

---

## 9. Примечания

- modDesc только ссылается на файл; наборы — во внешнем `<missionVehicles>`-файле.
- Иерархия `<mission type>` → `<group size/rewardScale/variant>` → `<vehicle filename>` (+ `<configuration>`).
- Техника набора обязана быть товаром магазина; на контракт она **выдаётся в аренду** и по завершении
  удаляется.
- Пул глобальный, аддитивный (карта + моды сливаются), без переопределения; выбор случайный по
  типу+размеру+варианту.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры. Базовый пул задаётся картой
  (`map.missionVehicles#filename`); базовые файлы данных в открытые исходники не входят. Атрибут
  размера — `size`.
