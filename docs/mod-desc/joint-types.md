# Farming Simulator 2025
## Элемент `<jointTypes>`

```xml
<jointTypes>
    <jointType name="myCoupler"/>
</jointTypes>
```

Регистрирует **кастомные типы сцепок** (attacher joint type) — имена, по которым точка навески техники
(`attacherJoint`) стыкуется с точкой присоединения орудия (`inputAttacherJoint`). Каждое имя добавляется
в **общий глобальный реестр** сцепок игры; совместимость навески решается **совпадением имени** сцепки на
обеих сторонах.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

Сцепка в FS — это пара «источник → орудие»: на технике-носителе есть точки `attacherJoint` (задняя
навеска, дышло, стрела погрузчика), на орудии — точки `inputAttacherJoint`. У каждой точки есть атрибут
`jointType` — **тип сцепки**. Стыковка возможна только если тип на носителе и типе на орудии **совпадают**.

Игра держит фиксированный набор базовых типов (`trailer`, `implement`, `cutter`, `frontloader` и т.д.).
`<jointTypes>` позволяет моду **добавить своё имя типа** в этот набор — например, чтобы сделать уникальную
сцепку, к которой подходят только определённые орудия, не пересекаясь с базовыми.

В отличие от `specializations`/`vehicleTypes`, реестр сцепок **общий и не неймспейсится** по имени мода
(см. раздел 4) — иначе техника и орудия из разных модов не смогли бы стыковаться.

---

## 2. Атрибуты `<jointType>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да | Имя типа сцепки. Регистрируется как есть (без префикса мода). Регистрозависимо. |

`<jointTypes>` необязателен (`minOccurs="0"`), один; `<jointType>` внутри может быть несколько. Других
атрибутов нет — ни `className`, ни `filename`, ни `index`.

В XSD `name` типизирован как `g_filename`, но это **не путь к файлу**: движок читает значение как строку
и использует только как идентификатор (ключ в таблице). Типизация `g_filename` — переиспользование
строкового типа в схеме, файловой семантики у атрибута нет.

---

## 3. Что происходит при загрузке

При загрузке мода движок для каждого `<jointType name="X">` вызывает `AttacherJoints.registerJointType("X")`:

1. Формируется ключ `JOINTTYPE_<X В ВЕРХНЕМ РЕГИСТРЕ>`.
2. Если такого типа ещё нет — счётчик `NUM_JOINTTYPES` увеличивается, новому типу присваивается
   очередной **целочисленный индекс**, и он кладётся в реестр под двумя ключами: константа
   `AttacherJoints.JOINTTYPE_<X>` и запись `jointTypeNameToInt["X"]`.
3. Если имя **уже зарегистрировано** — вызов ничего не делает (индекс не переприсваивается, значение не
   перезаписывается). Поэтому повторно объявлять базовый тип (`trailer` и т.п.) бессмысленно и безвредно.

То есть тип — это просто имя, отображённое на целое число. Вся стыковка работает по этим числам.

---

## 4. Глобальный реестр (не неймспейсится)

Имя типа регистрируется **как есть, без префикса мода**. Реестр один на всю игру: тип, добавленный
модом A, виден моду B и базовой игре. Это осознанное отличие от `specializations`, `vehicleTypes`,
`placeableTypes`, `handToolTypes`, где имя всегда получает префикс `<modName>.<name>`.

Причина: сцепка — это контракт между **разными** объектами (носитель и орудие), нередко из разных модов.
Если бы имя неймспейсилось, `jointType` носителя из одного мода никогда не совпал бы с `jointType` орудия
из другого. Общий реестр и совпадение по имени как раз и обеспечивают межмодовую стыковку.

Практическое следствие: имя кастомного типа стоит делать **уникальным** (например с префиксом-подсказкой
`myMod_coupler`), чтобы случайно не столкнуться с типом другого мода — но это соглашение об именовании,
а не механизм движка.

---

## 5. Как техника ссылается на тип сцепки

`jointType` указывается **в XML техники**, не в modDesc. Две стороны:

- **Носитель** (трактор, тележка, стрела): `vehicle.attacherJoints.attacherJoint#jointType`
  (строка, значение по умолчанию `implement`).
- **Орудие**: `vehicle.attachable.inputAttacherJoints.inputAttacherJoint#jointType`
  (строка, без значения по умолчанию — если не задать, будет предупреждение `Missing jointType`).

```xml
<!-- на носителе -->
<attacherJoints>
    <attacherJoint node="attacherJoint01" jointType="myCoupler"/>
</attacherJoints>

<!-- на орудии -->
<attachable>
    <inputAttacherJoints>
        <inputAttacherJoint node="inputAttacherJoint01" jointType="myCoupler"/>
    </inputAttacherJoints>
</attachable>
```

При загрузке строка `jointType` переводится в целочисленный индекс через `jointTypeNameToInt`.
Совместимость проверяется **равенством индексов**: орудие подходит к точке носителя, только если
`inputAttacherJoint.jointType == attacherJoint.jointType`. Поэтому регистрации самой по себе
недостаточно — новый тип должен стоять **на обеих сторонах**.

Значение **регистрозависимо**: `trailerLow` сработает, а `trailerlow` или `TrailerLow` — нет
(будет предупреждение и откат к запасному типу).

Неизвестное имя: на стороне носителя — лог `Invalid jointType` и откат к `implement`; на стороне орудия —
предупреждение и откат к `trailer`/`trailerLow`/`implement` в зависимости от флагов.

---

## 6. Базовые типы сцепок

Базовый набор типов (по категориям):

| Категория | Имена типов |
|---|---|
| Орудия / общее | `implement` |
| Прицепы | `trailer`, `trailerLow`, `trailerCar`, `trailerSaddled`, `semitrailer`, `semitrailerHook`, `semitrailerCar` |
| Погрузчики | `frontloader`, `attachableFrontloader`, `telehandler`, `wheelLoader`, `loaderFork`, `skidSteer` |
| Жатки | `cutter`, `cutterHarvester`, `cutterTrailer` |
| Прочее | `manureBarrel`, `conveyor`, `hookLift`, `bigBag`, `train` |

Точные строки: `conveyor` (не `conveyorBelt`); типов `fastCoupler` и `semitrailerLow` в базовом наборе
нет. Список подтверждён по коду (`AttacherJoints.lua`).

Свой тип нужен нечасто: базовые покрывают большинство сцепок, и реальные моды почти всегда переиспользуют
их. `<jointTypes>` оправдан, когда нужна сцепка, к которой намеренно **не** подходят стандартные орудия.

---

## 7. Пример: полная кастомная сцепка

Регистрация типа в modDesc + использование на обеих сторонах:

```xml
<!-- modDesc.xml -->
<jointTypes>
    <jointType name="myCoupler"/>
</jointTypes>
```

```xml
<!-- носитель: myMod/vehicles/carrier.xml -->
<attacherJoints>
    <attacherJoint node="attacherJoint01" jointType="myCoupler"/>
</attacherJoints>
```

```xml
<!-- орудие: myMod/vehicles/tool.xml -->
<attachable>
    <inputAttacherJoints>
        <inputAttacherJoint node="inputAttacherJoint01" jointType="myCoupler"/>
    </inputAttacherJoints>
</attachable>
```

## 8. Типичные ошибки

- **Тип зарегистрирован только на одной стороне** — если `jointType` стоит у носителя, но ни одно орудие
  его не использует (или наоборот), стыковаться не с чем. Нужны обе стороны с одинаковым именем.
- **Расчёт на неймспейс мода** — тип не получает префикс `<modName>.`; в XML пишут ровно
  зарегистрированное имя.
- **Регистр** — `jointType` регистрозависим; расхождение в регистре ломает стыковку.
- **Повторная регистрация базового типа** — безвредна, но бессмысленна (уже зарегистрирован, вызов —
  no-op).
- **Слишком общее имя** — совпадение с типом другого мода приведёт к незапланированной совместимости;
  имя кастомного типа лучше делать уникальным.
- **Ожидание, что имя — это файл** — `name` не путь; ссылка на `.xml`/`.lua` здесь бессмысленна.

---

## 9. Примечания

- Реестр сцепок общий и глобальный; имя не неймспейсится — этим `<jointTypes>` принципиально отличается
  от блоков спек/типов.
- Совместимость решается равенством целочисленных индексов, в которые переводятся имена; регистрация
  лишь заводит имя в реестр.
- Значения `jointType` указываются в XML техники (`attacherJoint` и `inputAttacherJoint`), а не в modDesc.
- Кастомные `<jointTypes>` в реальных модах встречаются редко (по ограниченной выборке ~20 модов —
  единичные случаи); базовые типы покрывают почти все сцепки.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры (`registerJointType`, пути XML,
  стыковка по индексам).
