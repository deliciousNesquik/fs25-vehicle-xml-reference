# Farming Simulator 2025
## Элемент `<handToolSpecializations>`

```xml
<handToolSpecializations>
    <specialization name="myTool"
                    className="HandToolMyTool"
                    filename="scripts/HandToolMyTool.lua"/>
</handToolSpecializations>
```

Регистрирует **кастомные спецификации ручных инструментов** (hand tool — переносимые игроком инструменты:
бензопила, фонарь, мойка высокого давления, щётка, баллончик и т.п.) — Lua-скрипты, добавляющие
инструменту новое поведение. Полный аналог `<specializations>`, но для класса `HandTool` вместо
`Vehicle`. Блок только объявляет спеку движку; чтобы она заработала, её отдельно добавляют к типу
инструмента (см. раздел 6 и страницу [handToolTypes](handtool-types.md)).

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.
>
> Кастомные спеки ручных инструментов объявляются в modDesc через `<handToolSpecializations>`; движок
> регистрирует их общим менеджером спецификаций (`g_handToolSpecializationManager`).

---

## 1. Что это

Спецификация (specialization) — модуль поведения инструмента в FS. `<handToolSpecializations>`
перечисляет собственные спеки мода для ручных инструментов: даёт каждой имя, указывает её класс и файл.
При загрузке мода движок регистрирует эти спеки и делает их доступными для добавления к типам
инструментов.

Движок использует для этого тот же общий менеджер спецификаций, что и для техники и размещаемых
объектов (`SpecializationManager`), только для домена «handTool» — синглтон
`g_handToolSpecializationManager`. Отличается только домен; сам механизм регистрации идентичен
`<specializations>`.

---

## 2. Атрибуты `<specialization>`

Все три обязательны.

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да | Имя спеки. Регистрируется с префиксом мода: `<modName>.<name>`. |
| `className` | STRING | да | Имя глобальной Lua-таблицы (класса) спеки. Регистрируется как `<modName>.<className>`. |
| `filename` | STRING | да | Путь к `.lua`-файлу спеки, относительно корня мода. |

`<handToolSpecializations>` необязателен (`minOccurs="0"`), один; `<specialization>` внутри может быть
несколько.

---

## 3. Что задаёт каждый атрибут

- **`name`** — короткое имя спеки. Движок регистрирует её под именем с префиксом мода:
  `<modName>.<name>`. По этому имени спеку добавляют к типам инструментов, а внутри инструмента её
  данные лежат в таблице `self["spec_<modName>.<name>"]`.
- **`className`** — имя **глобальной таблицы** Lua, объявленной в файле спеки. Поскольку файл лежит в
  моде, класс регистрируется с префиксом окружения мода: `<modName>.<className>`.
- **`filename`** — путь к файлу скрипта от корня мода. Файл загружается при регистрации.

---

## 4. Что происходит при загрузке

При загрузке мода движок для каждого `<specialization>`:

1. Загружает файл `filename` (в нём должна появиться глобальная таблица `className`).
2. Регистрирует спеку под именем `<modName>.<name>` в `g_handToolSpecializationManager`.

После этого спека **доступна**, но ещё ни к какому типу инструментов не привязана.

---

## 5. Что содержит класс спеки

Таблица `className` реализует стандартный интерфейс спецификации FS (детали — уже область
скриптинга): проверку предпосылок (`prerequisitesPresent`), регистрацию функций, событий и слушателей
(`registerFunctions`, `registerEventListeners`), регистрацию путей XML (`registerXMLPaths` под общей
схемой `handTool` + `setXMLSpecializationType`), и обработчики загрузки/обновления. Данные экземпляра
спека хранит в `self["spec_<modName>.<name>"]`.

Ручной инструмент **не «занимается»** как техника (нет enter/leave): его подбирает держатель
(`HandToolHolder`) и «несёт» игрок. Обработчики спеки инструмента ориентированы на этот цикл
удержания, а не на посадку в кабину.

---

## 6. Регистрация ≠ использование

Объявление в `<handToolSpecializations>` только **регистрирует** спеку. Чтобы она реально применилась
к инструменту, её надо **добавить к типу** одним из способов:

- **Декларативно** — объявить кастомный тип инструмента в [`<handToolTypes>`](handtool-types.md),
  перечислив в нём эту спеку, и указывать этот тип в XML инструмента (`<handTool type="...">`).
- **Кодом** — прикрепить спеку к существующим типам через хук менеджера типов.

Если этого не сделать, скрипт будет зарегистрирован, но не выполнится ни на одном инструменте.

---

## 7. Пример

Одна своя спека (регистрируется в моде, затем включается в собственный тип на странице
[handToolTypes](handtool-types.md)):

```xml
<handToolSpecializations>
    <specialization name="myTool" className="HandToolMyTool" filename="scripts/HandToolMyTool.lua"/>
</handToolSpecializations>
```

---

## 8. Типичные ошибки

- **`className` не совпадает** с именем глобальной таблицы в файле — движок не найдёт функции спеки.
- **Неверный `filename`** (путь/регистр) — файл не загрузится.
- **Забыли добавить спеку к типу инструмента** (раздел 6) — спека зарегистрирована, но не работает.
- **Путаница `name` и `className`** — `name` это имя спеки (для привязки к типам), `className` это
  Lua-таблица.

---

## 9. Примечания

- Имя спеки всегда неймспейсится модом: `<modName>.<name>`, класс — `<modName>.<className>`.
- Данные спеки на инструменте — в `self["spec_<modName>.<name>"]`; функции регистрируются на таблице
  типа и копируются на экземпляр — как у техники.
- Ручной инструмент, техника и placeable используют один и тот же движковый механизм спек
  (`SpecializationManager`); различаются домен и базовый класс — у инструмента это `HandTool`
  (наследник `Object`).
- Внутренняя реализация класса спеки — скриптинг Lua; данный справочник описывает только XML-объявление.
- Поведение — по движку FS25. Открытого мода с реальным (не шаблонным) блоком в публичном доступе
  найти не удалось — примеры построены по подтверждённой механике.
