```xml
<uniqueType>myModFamily</uniqueType>
```

Строковый тег, делающий моды **взаимоисключающими**: одновременно можно включить только один мод с
данным `uniqueType`. Используется для вариантов/редакций одного мода и конкурирующих модов, которые
нельзя держать активными вместе.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

`<uniqueType>` — произвольная строка-метка, задаваемая автором. Если у нескольких модов она
одинаковая, игра не даёт включить больше одного из них. Элемент необязателен; без него мод ничем
не ограничен.

---

## 2. Характеристики

| Свойство | Значение |
|---|---|
| Тип | STRING[^string] — элемент с текстом-тегом (не атрибут). |
| Обязателен | нет (`minOccurs="0"`). |
| По умолчанию | нет (отсутствует = ограничения нет). |
| Атрибуты | нет. |

---

## 3. Что делает

Моды с **одинаковым** значением `uniqueType` образуют группу «только один включённый». Значение —
произвольный тег; чтобы два мода исключали друг друга, у них должен быть **побайтово одинаковый**
`uniqueType`. Разные теги (или отсутствие тега) — независимы.

---

## 4. Как это в экране выбора модов

Это не молчаливая блокировка и не авто-снятие, а **подтверждение со свопом**:

- Первый мод с данным тегом включается обычно.
- Попытка включить **второй** мод того же тега → всплывает диалог Yes/No (с названиями текущего и
  нового мода). «Да» — старый выключается, новый включается (замена). «Нет» — остаётся текущий.
- Кнопка «Выбрать все» из каждой группы одного тега оставит только один мод (первый по алфавиту
  названия), остальные тихо не включатся.

---

## 5. Значение-тег

- Тег придумывает автор; смысловой строки достаточно (например `myMod_hud`, `brandX_pack`).
- **Не оставлять пустым** (`<uniqueType/>`): пустой тег может объединить в одну взаимоисключающую
  группу все моды с пустым тегом. Либо задавать осмысленную строку, либо убирать элемент.

---

## 6. Применение

- Редакции/варианты одного мода (например «lite» и «full»), которые не должны работать вместе.
- Конкурирующие HUD/скрипты одного назначения.

Поле нишевое: в большинстве модов не используется (обычной технике не нужно).

---

## 7. Мультиплеер

- Ограничение работает в клиентском экране выбора модов (одиночная игра, хост).
- На матчинг модов при подключении к серверу `uniqueType` **не влияет** — совместимость проверяется
  по хешу/имени мода, а не по этому тегу.
- Выделенный сервер включает моды через веб-панель — обрабатывается ли там `uniqueType`, из
  открытых источников не подтверждается.

---

## 8. Примеры

Два варианта одного мода, взаимоисключающие:

```xml
<!-- modDesc варианта A -->
<uniqueType>myTrailer_pack</uniqueType>
```
```xml
<!-- modDesc варианта B -->
<uniqueType>myTrailer_pack</uniqueType>
```

---

## 9. Типичные ошибки

- **Пустой `<uniqueType/>`** — может связать все пустые в одну группу; не оставлять пустым.
- **Ожидание тихого авто-снятия** — на самом деле показывается диалог замены.
- **Считать, что влияет на загрузку/матчинг в MP** — это только UX-ограничение выбора, не серверная проверка.
- **Разный регистр/опечатка в теге** — тогда моды не будут исключать друг друга (совпадение точное).

---

## 10. Примечания

- Значение — произвольный тег; исключение действует между модами с идентичным тегом.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры.
- Поле малоиспользуемое; для обычной техники не требуется.
