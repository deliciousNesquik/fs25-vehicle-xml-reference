```xml
<storeCategories>
    <storeCategory name="myTools" title="$l10n_category_myTools" image="icons/cat.dds" type="TOOL"/>
</storeCategories>
```

Объявляет **кастомные категории магазина** — вкладки-разделы, в которые попадают товары. Каждая
`<storeCategory>` задаёт имя-идентификатор, отображаемый заголовок, иконку, тип (секцию магазина) и
позицию в списке. На категорию затем ссылаются предметы полем `<storeData><category>`.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.
>
> **Важно:** через modDesc этот блок читается **только у DLC** (файл-дескриптор `dlcDesc.xml`).
> Обычный мод (`modDesc.xml`) его молча игнорирует — см. раздел 3.

---

## 1. Что это

Магазин группирует товары по категориям; каждая категория принадлежит одному из типов-секций
(`VEHICLE`, `TOOL`, `PLACEABLE`, `OBJECT`). `<storeCategories>` позволяет DLC добавить свою категорию, а
предметы ссылаются на неё по имени. Базовые категории игры заданы в `dataS/storeCategories.xml`.

Обычный мод новую категорию через modDesc завести **не может** (раздел 3) — он либо кладёт товары в
существующую базовую категорию (`<storeData><category>`), либо регистрирует категорию скриптом.

---

## 2. Атрибуты `<storeCategory>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да (практически) | Имя-идентификатор. Приводится к ВЕРХНЕМУ регистру при регистрации и поиске; должно быть валидным индекс-именем. По нему ссылаются в `<storeData><category>`. |
| `title` | STRING | нет | Заголовок категории. `$l10n_<ключ>` резолвится через локализацию мода; иначе — обычный текст. |
| `image` | STRING | нет | Иконка категории. Путь относительно корня мода. |
| `type` | STRING | нет | Тип-секция: `VEHICLE`, `TOOL`, `PLACEABLE`, `OBJECT` (раздел 4). |
| `insertAfter` | STRING | нет | Имя существующей категории, **после** которой встанет новая в списке (FS25; раздел 5). |

`<storeCategories>` необязателен (`minOccurs="0"`), один; `<storeCategory>` внутри может быть несколько.

---

## 3. Только для DLC + скриптовый обход

При загрузке движок читает `modDesc.storeCategories.storeCategory` **только если** дескриптор — файл DLC
(имя оканчивается на `dlcDesc.xml`). Обычный мод грузится с `modDesc.xml`, поэтому блок пропускается
**молча**, без предупреждения. Для сравнения: `<brands>` читаются у всех модов.

Обычному моду доступны два пути:

- **Использовать базовую категорию** — просто указать её имя в `<storeData><category>` товара.
- **Зарегистрировать категорию скриптом** — вызвать `g_storeManager:addCategory(...)` (или
  `g_storeManager:loadCategoryFromXML(...)`) из Lua мода. У самой функции DLC-проверки нет — ограничение
  живёт только в разборе modDesc. Это распространённый приём модов (внешняя практика, не часть схемы).

---

## 4. Атрибут `type` — секция магазина

`type` относит категорию к одной из верхнеуровневых секций магазина. Подтверждённые значения:
`VEHICLE`, `TOOL`, `PLACEABLE`, `OBJECT` (плюс пустое `NONE`). Значения `MISC`/`DRIVABLES`/`TRAILERS`,
встречающиеся в некоторых шаблонах, — это **имена категорий**, а не типы; как `type` они недостоверны.

При **неизвестном** `type` категория **отклоняется** (`CategoryType ... is not defined!`): тип должен
быть заранее зарегистрирован (типы данными загружаются из `dataS/storeCategories.xml`).

Новый **тип** (новую вкладку магазина) мод/DLC добавить не может — доступно лишь добавление категории
внутри существующего типа.

---

## 5. Позиция в списке: `insertAfter`

`insertAfter` задаёт имя существующей категории, сразу **после** которой встанет новая; порядок всего
списка затем пересчитывается. Если `insertAfter` не задан или не найден — категория добавляется в конец.
Атрибут `insertAfter` присутствует в актуальной XSD.

---

## 6. Как товар ссылается на категорию

В файле предмета: `<storeData><category>имя</category>` (см. [storeItems](store-items.md)). Резолвится
**по имени** (регистр не важен, приводится к верхнему). Можно указать несколько категорий через пробел.
Неизвестное имя даёт предупреждение; при пустом значении действует запасная категория `MISC`
(значение по умолчанию в схеме `storeData.category`).

---

## 7. Базовые категории

Базовые категории игры заданы в `dataS/storeCategories.xml` (в открытые исходники не входит, поэтому
полный список имён первоисточником не подтверждается). Типы-секции — `VEHICLE`, `TOOL`, `PLACEABLE`,
`OBJECT`.

Имена базовых категорий, подтверждённые прямыми ссылками из реальных модов (`<storeData><category>`):

- Техника/орудия: `cottonVehicles`, `mulchers`, `rollers`, `manureSpreaders`, `pallets`.
- Размещаемые: `placeableMisc`, `productionPoints`, `silos`, `misc`.

Отдельно: у размещаемых объектов внутри блока кисти строительства есть **своя** категория
(`<brush><category>buildings</category>` / `production`) — это категория меню строительства, не путать с
категорией магазина.

---

## 8. Пример

Иллюстративный блок (по одной категории на каждую секцию магазина; `title` — ключ локализации, `image` —
`.dds` в моде):

```xml
<storeCategories>
    <storeCategory name="myVehicles"  title="$l10n_category_myVehicles"  image="icons/catVehicle.dds"  type="VEHICLE"/>
    <storeCategory name="myTools"     title="$l10n_category_myTools"     image="icons/catTool.dds"     type="TOOL"/>
    <storeCategory name="myObjects"   title="$l10n_category_myObjects"   image="icons/catObject.dds"   type="OBJECT"/>
    <storeCategory name="myBuildings" title="$l10n_category_myBuildings" image="icons/catPlaceable.dds" type="PLACEABLE"/>
</storeCategories>
```

Товар в такой категории (в файле предмета):

```xml
<storeData>
    <category>myTools</category>
    ...
</storeData>
```

## 9. Типичные ошибки

- **Ожидание, что сработает в обычном моде** — блок читается только у DLC; иначе молча игнорируется.
  Обычному моду — базовая категория в `storeData` или регистрация скриптом.
- **Невалидное `name`** — категория не зарегистрируется (нужно валидное индекс-имя).
- **Неизвестный `type`** — категория отбрасывается.
- **`type` со значением имени категории** (`MISC`/`TRAILERS`) — это не тип-секция; товар не попадёт в
  задуманную вкладку.
- **Ссылка на несуществующую категорию в `storeData`** — предупреждение; товар осядет в `MISC`.

---

## 10. Примечания

- Через modDesc `<storeCategories>` регистрируются только у DLC; обычные моды используют базовые
  категории или скрипт (`g_storeManager:addCategory`).
- `name` неймспейсом мода не префиксится (в отличие от спек/типов) — это глобальное имя категории;
  стоит делать его уникальным.
- `title` — `$l10n_`-ключ или текст; `image` — путь в моде; `type` — секция магазина.
- Новую верхнеуровневую вкладку (тип) добавить нельзя — только категорию внутри существующего типа.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры. Полный список
  базовых имён категорий из открытых исходников не читается (файл `dataS/storeCategories.xml`
  отсутствует); подтверждённые имена — из реальных модов. Реального мода на GitHub с блоком
  `<storeCategories>` в modDesc практически нет (механизм DLC-only); пример иллюстративный.
