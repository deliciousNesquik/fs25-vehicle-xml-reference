```xml
<extraSourceFiles>
    <sourceFile filename="scripts/script.lua"/>
</extraSourceFiles>
```

Подключает **дополнительные Lua-скрипты**, которые загружаются глобально при старте мода. В отличие
от `<specializations>`, это не спеки техники, а обычные скрипты, выполняемые один раз (event-классы,
инжекторы интерфейса, менеджеры и т.п.). Внутренности самих скриптов — область скриптинга, вне
объёма справочника.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

`<extraSourceFiles>` перечисляет Lua-файлы, которые движок «сорсит» (загружает и выполняет) при
загрузке мода. Каждый файл — элемент `<sourceFile>` с путём. Так в игру добавляют глобальную
логику, не привязанную к конкретной технике.

---

## 2. Атрибуты `<sourceFile>`

| Атрибут | Тип | Описание |
|---|---|---|
| `filename` | STRING[^string] | Путь к `.lua`-файлу, относительно корня мода. |

`<extraSourceFiles>` необязателен (`minOccurs="0"`), один; `<sourceFile>` внутри может быть несколько.

---

## 3. Что делает

При загрузке мода движок выполняет каждый указанный файл **один раз в глобальной среде** (аналог
Lua `source()`). Это не спека: файл не привязывается к технике и не имеет жизненного цикла
`onLoad`/`onUpdate` сам по себе — он просто исполняется на старте.

Документация схемы прямо называет это «additional lua file to source».

---

## 4. Порядок важен

Файлы выполняются **в порядке перечисления**. Если один скрипт зависит от другого (использует его
таблицу/функции), зависимость должна идти **выше** по списку.

Пример из реального мода: файл-контроллер страницы объявляется раньше, чем инжектор, который его
использует:

```xml
<extraSourceFiles>
    <sourceFile filename="scripts/gui/SpillSettingsPage.lua"/>
    <sourceFile filename="scripts/gui/SpillSettingsGui.lua"/>
</extraSourceFiles>
```

---

## 5. Тайминг и область

- Загрузка — на этапе загрузки мода, до старта миссии.
- На этом этапе глобали `g_currentModDirectory` и `g_currentModName` валидны, поэтому их часто
  фиксируют в локальную переменную прямо при выполнении файла (в рантайме, вне загрузки, они уже могут быть `nil`).
- Среда глобальная: объявленные в файле таблицы/функции доступны всему моду.

---

## 6. `<extraSourceFiles>` или `<specializations>`

| Признак | `<extraSourceFiles>` | `<specializations>` |
|---|---|---|
| Что это | обычный глобальный скрипт | класс-спека поведения техники |
| Когда выполняется | один раз при загрузке мода | на каждой технике с этой спекой |
| Привязка к технике | нет | да (через тип техники) |
| Жизненный цикл (`onLoad`/`onUpdate`) | нет (сам по себе) | да |
| Типичное применение | event-классы, GUI, менеджеры, хуки | новое поведение техники |

Спеку техники нужно объявлять в `<specializations>`, а не в `<extraSourceFiles>`.

---

## 7. Для чего используют

Через `<extraSourceFiles>` подключают глобальную логику, не относящуюся к одной технике:

- классы сетевых событий (регистрируются при загрузке);
- инжекторы/контроллеры интерфейса (встройка в меню игры);
- глобальные менеджеры и системы;
- хуки на базовые функции игры (например через перехват при загрузке).

Детали реализации этих скриптов — скриптинг Lua, за рамками данного справочника.

---

## 8. Примеры

Один скрипт:

```xml
<extraSourceFiles>
    <sourceFile filename="scripts/main.lua"/>
</extraSourceFiles>
```

Несколько с учётом порядка (зависимость выше):

```xml
<extraSourceFiles>
    <sourceFile filename="scripts/events/MyEvent.lua"/>
    <sourceFile filename="scripts/MySystem.lua"/>
</extraSourceFiles>
```

---

## 9. Типичные ошибки

- **Неверный порядок** — скрипт использует таблицу, которая объявляется ниже по списку → `nil`
  при обращении.
- **Неверный путь/регистр** в `filename` — файл не загрузится.
- **Спека техники здесь вместо `<specializations>`** — как обычный скрипт она не привяжется к
  технике и не получит жизненного цикла.
- **Расчёт на `g_currentModDirectory` в рантайме** — он валиден при загрузке файла, но позже уже `nil`;
  фиксировать значение на этапе выполнения файла.

---

## 10. Примечания

- `<extraSourceFiles>` — про глобальные скрипты; поведение техники — через `<specializations>`.
- Файлы выполняются один раз при загрузке мода, в порядке перечисления.
- Внутренняя реализация скриптов — скриптинг; справочник описывает только XML-подключение.
