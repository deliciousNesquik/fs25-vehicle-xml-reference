```xml
<consumables>
    <consumable xmlFilename="xml/myWrapFoil.xml"/>
</consumables>
```

Подключает **расходники** — предметы, которые техника несёт и **тратит по мере работы**, а потом
пополняет (штатный кейс FS25 — плёнка/сетка/шпагат для обмотки тюков). В modDesc это только список
**ссылок на внешние файлы**: каждый `<consumable>` содержит `xmlFilename`, указывающий на XML с
определением вариаций расходника.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.
>
> Расходники (`ConsumableManager`) объявляются в modDesc списком ссылок на внешние файлы вариаций.

---

## 1. Что это

Расходник — это **надстройка над `FillUnit`** техники: не отдельный тип груза, а предмет, который
визуально везётся, выбирается по бренду/варианту и **расходуется за единицу работы**, с пополнением за
деньги. В FS25 так сделана обмотка тюков (плёнка/сетка/шпагат разных брендов и цветов).

Расходники регистрируются в общем реестре (`g_consumableManager`); техника через специализацию
`Consumable` привязывает **тип** расходника к своему `fillUnit`, тратит его при работе и показывает
предупреждение при опустошении.

Читается у **всех** модов (не только DLC); разбор отложен: сначала базовый файл, затем файлы модов.

---

## 2. Атрибут `<consumable>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `xmlFilename` | STRING[^string] | да (практически) | Путь к внешнему XML с вариациями расходника. Относительно корня мода; `$data/…` — от корня игры. |

`<consumables>` необязателен (`minOccurs="0"`), один; `<consumable>` внутри может быть несколько.

---

## 3. Как загружается

- modDesc читает `modDesc.consumables.consumable#xmlFilename` → ставит файл в очередь
  (`g_consumableManager:addModConsumable(...)`, окружение = имя мода); путь относительно мода.
- Разбор **отложен**: в `loadMapData` сначала грузится базовый файл (типы расходников), затем файлы модов
  (`loadConsumableVariationsFromXML`).
- Не DLC-only.

---

## 4. Внешний файл (вариации расходника)

Корень внешнего файла, на который ссылается modDesc, — `<consumable>`; внутри — `<consumableVariation>`
(варианты: бренды/цвета плёнки и т.п.).

Атрибуты `<consumableVariation>`:

| Атрибут | По умолчанию | Описание |
|---|---|---|
| `type` | — | Тип расходника, к которому относится вариация (типы объявляет базовый список расходников). |
| `name` | — | Внутреннее имя вариации (у мода неймспейсится: `<modName>.<name>`). |
| `title` | — | Название в UI (l10n). |
| `price` | `0` | Цена за единицу (списывается при пополнении). |
| `capacity` | `1` | Ёмкость в единицах. |
| `unitText` | — | Подпись единицы (l10n). |

Дочерние: `<object filename node>` (модель), `<consumingObject filename node>` (расходуемая модель),
`<tensionBeltObject filename node>` (стяжной ремень), `<metaData><value name value>`,
`<shaderParameter name materialSlotName value>` (VEC4 — например цвет плёнки). Повторное имя вариации
отклоняется; есть лимит числа вариаций.

**Типы** расходников задаёт список расходников игры (`<consumables><types><type name title>`); мод обычно
добавляет **вариации** к существующему типу (новые цвета/бренды плёнки).

---

## 5. Как техника использует расходник

Специализация `Consumable` (требует `FillUnit`). В XML техники:

```xml
<consumable>
    <type typeName="..." defaultConsumableName="..." fillUnitIndex="1" allowRefillDialog="true" showWarning="true"/>
</consumable>
```

- `typeName` — тип расходника, который держит машина; `defaultConsumableName` — вариация по умолчанию;
  `fillUnitIndex` — привязанный fillUnit; `allowRefillDialog`/`showWarning` — диалог пополнения/предупреждение.
- При работе `consumingFillLevel` уменьшается, расход берётся из fillUnit; при опустошении — предупреждение
  `warning_consumableEmpty`.
- Пополнение — через диалог выбора вариации (`ConsumableActivatable`) → событие `ConsumableRefillEvent`,
  которое **списывает деньги** (`MoneyType.PURCHASE_CONSUMABLES`).
- Конфигурации: `vehicle.consumable.<...>Configurations` с `#consumableName`.

---

## 6. Чем отличается от fillTypes

Расходник — **не тип груза**, а слой поверх `FillUnit`:

- дискретные слоты хранения/расхода с отдельными визуальными мешами (и поведением паллеты/стяжного ремня);
- **вариации** (бренд/цвет/цена/i3d/shader-параметры), выбираемые при пополнении;
- отдельный `consumingFillLevel`, «съедаемый» по мере работы (анимация/масштаб/shader `amount`);
- экономика «покупка при пополнении»;
- предупреждение о пустоте + диалог пополнения.

У обычного [fillType](fill-types.md) ничего из этого нет — поэтому под плёнку/сетку сделан отдельный
механизм.

---

## 7. Неймспейс и переопределение

- Вариации хранятся **глобально**; вариации мода **неймспейсятся** окружением мода
  (`<modName>.<name>`). Поиск: сначала `<modName>.<name>`, затем голое имя — свои и базовые сосуществуют.
- Повторное имя вариации → пропуск с предупреждением. Имена типов — в верхнем регистре.
- Базовый файл расходников — в данных игры (в открытые исходники не входит; путь-константа в дампе
  вырезана; по конвенции `data/consumables/…`).

---

## 8. Пример

modDesc — подключение файла вариаций:

```xml
<consumables>
    <consumable xmlFilename="xml/myWrapFoil.xml"/>
</consumables>
```

Файл вариаций (root `<consumable>`) — своя вариация обмотки для существующего типа:

```xml
<consumable>
    <consumableVariation type="BALEWRAP" name="myGreenFoil" title="$l10n_foil_green" price="30" capacity="25" unitText="$l10n_unit_pieces">
        <object filename="objects/foilRoll.i3d" node="0"/>
        <shaderParameter name="colorScale" materialSlotName="wrap" value="0.1 0.5 0.1 1"/>
    </consumableVariation>
</consumable>
```

(Имена типов/точная схема базового набора — из данных игры; пример иллюстративный.)

---

## 9. Типичные ошибки

- **Инлайн-определения в modDesc** — нельзя; `<consumable>` только `xmlFilename`, вариации в отдельном файле.
- **`type` не существует** — вариация относится к несуществующему типу; тип должен быть объявлен (обычно
  базовой игрой).
- **Повторное имя вариации** — пропускается с предупреждением.
- **Путать с fillType** — расходник это слой над fillUnit, не тип груза.
- **Нет у техники спеки `Consumable`/`fillUnit`** — расходник некуда привязать.

---

## 10. Примечания

- Механизм `ConsumableManager`.
- modDesc только ссылается на файл; вариации — во внешнем `<consumable>`-файле.
- Расходник — надстройка над `FillUnit`: вариации (бренд/цвет/цена/меши/shader), расход при работе,
  пополнение за деньги, предупреждение о пустоте.
- Вариации глобальны; у мода неймспейсятся (`<modName>.<name>`); дубликат имени пропускается.
- Штатное применение — обмотка тюков (плёнка/сетка/шпагат); мод обычно добавляет вариации к базовому типу.
- Механика подтверждена по исходникам FS25 (`misc/ConsumableManager.lua`,
  `vehicles/specializations/Consumable.lua`, `ConsumableActivatable.lua`, `ConsumableRefillEvent.lua`).
  Точная строка чтения `modDesc.consumables` (mission-слой) и путь базового файла в открытые дампы не
  входят.
