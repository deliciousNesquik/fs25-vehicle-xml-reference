```xml
<actions>
    <action name="BMP_DISEASE_MINIMAP_TOGGLE" category="ONFOOT VEHICLE"/>
</actions>
```

Регистрирует **действия ввода** (input actions) мода — именованные управляющие команды, которым игрок
может назначить клавишу/кнопку. Действие появляется в меню «Управление» и сохраняется в конфиге игрока.
Пара к [`<inputBinding>`](input-binding.md): здесь действие объявляется, там задаётся его привязка по
умолчанию; в Lua действие используется через `g_inputBinding:registerActionEvent`.

> Расположение: дочерний элемент `<modDesc>`. Раздел справочника — modDesc.

---

## 1. Что это

Действие ввода — это абстрактная команда («переключить миникарту», «открыть меню»), отвязанная от
конкретной клавиши. Игра держит набор базовых действий (`dataS/inputActions.xml`); `<actions>` добавляет
свои. При загрузке действия мода вливаются в **те же глобальные таблицы**, что и базовые (список
действий + карта имён), поэтому становятся полноценными: показываются в «Управлении», сохраняются в
`config/inputBinding.xml` игрока.

Имя действия — единый ключ, связывающий три места: `<actions>` (объявление) →
[`<inputBinding>`](input-binding.md) (привязка по умолчанию) → Lua `registerActionEvent` (поведение).

---

## 2. Атрибуты `<action>`

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `name` | STRING[^string] | да | Идентификатор действия. Регистрозависимый, **без префикса мода** (глобальный). Становится `InputAction.<name>` в Lua. |
| `axisType` | STRING | нет | `HALF` (по умолчанию) или `FULL` — тип оси (раздел 4). |
| `category` | STRING | нет | Список через пробел: `SYSTEM` / `ONFOOT` / `VEHICLE` — домен конфликта привязок (раздел 5). |
| `displayCategory` | STRING | нет | Группа в меню «Управление». Для модов **игнорируется** — переопределяется названием мода (раздел 6). |
| `ignoreComboMask` | BOOL[^bool] | нет | По умолчанию `false`. `true` — действие срабатывает даже при зажатом модификаторе комбо. |

`<actions>` необязателен (`minOccurs="0"`), один; `<action>` внутри может быть несколько.

Помимо перечисленных в XSD, движок также читает `locked` (запрет переназначения и исключение из проверки
конфликтов), `isBaseAction`, `isConsoleAction`, `isMobileAction` (платформенные ограничения) — эти
атрибуты в публичной схеме не указаны.

---

## 3. Имя действия (`name`)

- Читается **как есть**, регистрозависимо; движок не приводит к верхнему регистру и **не неймспейсит** по
  моду. По соглашению имена пишут в `ВЕРХНЕМ_РЕГИСТРЕ` с префиксом мода (`UNIVERSALAUTOLOAD_…`, `AD…`,
  `CP_…`, `BMP_…`), но это конвенция, а не требование.
- Регистрируется как глобальная константа `InputAction.<name>` — по ней действие вызывают из Lua.
- **Глобально:** если имя уже существует (базовое или чужого мода), новое действие занимает тот же слот и
  **наследует** уже имеющиеся привязки. Одноимённые действия схлопываются в одно — уникальный префикс в
  имени защищает от коллизии.

---

## 4. `axisType` — тип оси

- **`HALF`** (по умолчанию, в т.ч. при пропущенном/неверном значении) — однонаправленное действие,
  «кнопочное»; одно отображаемое имя.
- **`FULL`** — двунаправленная аналоговая ось; получает **два** имени — положительное и отрицательное
  (например «газ/тормоз», «осмотреться»). Локализуется ключами `input_<name>_1` и `input_<name>_2`.

Пропуск атрибута даёт `HALF`.

---

## 5. `category` — домен конфликта

Список через пробел из `SYSTEM`, `ONFOOT`, `VEHICLE` (неизвестные токены молча игнорируются). Это
**функциональный домен**, а не группа меню: два действия конфликтуют за одну привязку, **только если**
их наборы категорий пересекаются. Действие с `category="ONFOOT VEHICLE"` активно и пешком, и в технике.

---

## 6. `displayCategory` и название в меню

- `displayCategory` формирует ключ локализации `$l10n_inputCategory_<значение>`. **Но для действий мода
  это значение переопределяется названием мода** — действия мода всегда группируются в «Управлении» под
  именем мода, независимо от `displayCategory`. Поэтому реальные моды на этот атрибут не полагаются.
- **Отображаемое имя** самого действия берётся из ключа локализации `input_<name>` (для `FULL`-оси —
  `input_<name>_1` и `input_<name>_2`), из **локализации мода**. Нет ключа → предупреждение и показ
  сырого имени действия.

---

## 7. Пример

Своё действие (реальный мод FS25_CropDiseases_BMP) — объявление, привязка по умолчанию и локализация:

```xml
<!-- modDesc.xml -->
<actions>
    <action name="BMP_DISEASE_MINIMAP_TOGGLE" category="ONFOOT VEHICLE"/>
</actions>

<inputBinding>
    <actionBinding action="BMP_DISEASE_MINIMAP_TOGGLE">
        <binding device="KB_MOUSE_DEFAULT" input="KEY_lalt KEY_backslash" index="1"/>
    </actionBinding>
</inputBinding>
```

```xml
<!-- l10n мода -->
<text name="input_BMP_DISEASE_MINIMAP_TOGGLE" text="Переключить миникарту болезней"/>
```

```lua
-- Lua мода
g_inputBinding:registerActionEvent(InputAction.BMP_DISEASE_MINIMAP_TOGGLE, self, callback, false, true, false, true)
```

Пустых атрибутов у `<action>` быть не обязано — многие моды пишут `<action name="CP_START_STOP"/>` и
задают всё в `<inputBinding>`.

---

## 8. Типичные ошибки

- **Неуникальное имя** — совпадение с базовым/чужим действием: действия схлопнутся в одно (наследуются
  чужие привязки). Использовать префикс мода.
- **Расчёт на `displayCategory`** — для модов не действует; группа в меню = название мода.
- **Нет ключа `input_<name>`** в локализации мода — в меню покажется сырое имя действия.
- **Ожидание, что `category` — это группа меню** — нет, это домен конфликта привязок.
- **`axisType` пропущен для аналоговой оси** — по умолчанию `HALF`; для двунаправленной оси указывать
  `FULL` явно.

---

## 9. Примечания

- Действия мода вливаются в общие таблицы движка (не отдельный неймспейс): видны в «Управлении»,
  сохраняются в `config/inputBinding.xml`, могут ссылаться на базовые действия.
- Имя — регистрозависимый глобальный идентификатор `InputAction.<name>`; связывает `<actions>`,
  [`<inputBinding>`](input-binding.md) и Lua `registerActionEvent`.
- Отображаемое имя — ключ `input_<name>` из локализации мода.
- Реализация обработчиков — скриптинг Lua; справочник описывает XML-объявление.
- Поведение — по официальной схеме FS25 (`modDesc.xsd`) и движку игры.
