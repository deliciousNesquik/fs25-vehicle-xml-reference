```xml
<?xml version="1.0" encoding="utf-8" standalone="no"?>
```

Первая строка любого XML-файла: modDesc, `<vehicle>`-конфиг, `.i3d`[^i3d], карты, сейвы,
локализация, звуки. Это пролог[^prolog] документа: он сообщает синтаксическому
анализатору[^parser] версию стандарта XML и кодировку[^encoding] символов, которыми записан файл.

> Расположение: самая первая строка файла, до любого содержимого. Раздел справочника — concepts.

---

## 1. Что это

Объявление XML (XML declaration) — служебная строка `<?xml … ?>` в начале документа. Она не
относится к технике или блокам конфигурации: это часть самого формата XML. Инструменты GIANTS
(редактор, игра при сохранении) записывают её в каждый файл автоматически, всегда в одном виде.

Строка задаёт три вещи: версию XML (`version`), кодировку файла (`encoding`) и признак
самодостаточности (`standalone`).

---

## 2. Атрибуты

| Атрибут | Обязателен | Значение в FS25 | Описание |
|---|---|---|---|
| `version` | да (внутри объявления) | `1.0` | Версия стандарта XML. |
| `encoding` | нет (по умолчанию UTF-8[^utf8]) | `utf-8` | Кодировка символов, которой записан файл. |
| `standalone` | нет (по умолчанию `no`) | `no` | Опирается ли документ на внешние объявления (DTD[^dtd]). |

Порядок атрибутов в объявлении **фиксированный**: `version`, затем `encoding`, затем `standalone`.
Это отличается от обычных элементов XML, где порядок атрибутов произвольный.

---

## 3. Значения `version`

| Значение | Описание |
|---|---|
| `1.0` | Базовый стандарт XML. Используется во всех файлах FS25. |
| `1.1` | Существует (добавляет некоторые управляющие символы Unicode), в FS не применяется. |

---

## 4. Значения `encoding`

Регистр значения не важен (`utf-8` и `UTF-8` эквивалентны).

| Значение | Описание |
|---|---|
| `utf-8` | Юникод[^unicode], переменная длина; поддерживает любые языки. Стандарт GIANTS для всех файлов FS25. |
| `utf-16` | Юникод, 2–4 байта на символ. В FS не применяется. |
| `iso-8859-1`, `windows-1251` | Однобайтовые кодировки под отдельные языки. В FS **не использовать**: ломают многоязычный текст. |

Значение `encoding` только **объявляет** кодировку — оно должно совпадать с тем, в какой
кодировке файл реально сохранён. Несовпадение портит все не-ASCII[^ascii] символы (кириллицу,
умляуты и т.п.).

---

## 5. Значения `standalone`

| Значение | Описание |
|---|---|
| `no` | Документ может опираться на внешние объявления (DTD, внешние сущности). Значение по умолчанию; его записывает GIANTS. |
| `yes` | Документ самодостаточен: внешних объявлений нет или они не влияют на содержимое. |

Атрибут имеет смысл только при наличии DTD. XML-файлы FS25 схемы DTD не используют, поэтому
`standalone` здесь функционально нейтрален — это просто значение, которое пишет сериализатор[^serializer] GIANTS.

---

## 6. Правила записи

- Объявление — **самая первая** строка файла. До него не должно быть ничего: ни пробелов, ни
  пустых строк, ни метки порядка байтов[^bom] (BOM).
- Открывающая часть `<?xml` пишется строчными буквами. `<?XML` недопустимо.
- Порядок атрибутов фиксирован: `version` → `encoding` → `standalone`.
- Формально объявление необязательно в XML 1.0, но инструменты GIANTS всегда его пишут, и файлы
  FS25 ожидаются с ним.

---

## 7. Зачем это в FS25

- **Кодировка.** Игра читает `encoding`, чтобы правильно раскодировать не-ASCII символы —
  названия и тексты на кириллице, немецкие умляуты и т.п. Без корректной кодировки такой текст
  превращается в «кракозябры».
- **Единый формат.** Все XML игры (от modDesc до `.i3d` и сейвов) начинаются с одной и той же
  строки, что упрощает и запись, и чтение файлов движком.
- **Совместимость.** `version="1.0"` гарантирует, что файл читается стандартным анализатором XML.

---

## 8. Примеры

Канонический вид (то, что пишет GIANTS):

```xml
<?xml version="1.0" encoding="utf-8" standalone="no"?>
```

Начало типового файла техники:

```xml
<?xml version="1.0" encoding="utf-8" standalone="no"?>
<vehicle type="...">
    ...
</vehicle>
```

Начало modDesc:

```xml
<?xml version="1.0" encoding="utf-8" standalone="no"?>
<modDesc descVersion="98">
    ...
</modDesc>
```

Допустимое сокращение (кодировка по умолчанию UTF-8, `standalone` опущен) — работает, но не
соответствует стилю GIANTS:

```xml
<?xml version="1.0"?>
```

---

## 9. Типичные ошибки

- **Что-либо перед объявлением** — пробел, пустая строка или BOM в начале файла: анализатор
  выдаёт ошибку «declaration must be first» или «content before prolog».
- **Объявленная кодировка ≠ реальной.** Файл сохранён в Windows-1251, а в объявлении `utf-8`
  (или наоборот) — не-ASCII символы отображаются неверно.
- **BOM у UTF-8-файла.** Некоторые редакторы Windows добавляют метку порядка байтов; часть
  анализаторов на ней спотыкается. Файлы FS сохраняются без BOM.
- **Прописные буквы** `<?XML …?>` — недопустимо.
- **Переставленные атрибуты** (`encoding` перед `version`) — нарушение формата объявления.

---

## 10. Примечания

- Строка относится ко всем XML игры одинаково — она не является блоком конфигурации техники.
- Менять её вручную обычно не требуется: инструменты GIANTS записывают корректный вариант сами.
- При ручном редактировании файла сохранять его следует в кодировке **UTF-8 без BOM**.

## Глоссарий

[^prolog]: Пролог — вводная часть XML-документа, включающая объявление `<?xml … ?>`. <https://en.wikipedia.org/wiki/XML#Prolog>
[^parser]: Синтаксический анализатор (parser) — программа, разбирающая текст файла по правилам формата. <https://en.wikipedia.org/wiki/Parsing>
[^encoding]: Кодировка — правило соответствия байтов файла и символов. <https://en.wikipedia.org/wiki/Character_encoding>
[^utf8]: UTF-8 — кодировка Unicode переменной длины, обратно совместимая с ASCII. <https://en.wikipedia.org/wiki/UTF-8>
[^unicode]: Unicode — стандарт, присваивающий номер каждому символу всех письменностей. <https://en.wikipedia.org/wiki/Unicode>
[^ascii]: ASCII — базовая 7-битная кодировка латиницы, цифр и знаков. <https://en.wikipedia.org/wiki/ASCII>
[^dtd]: DTD (Document Type Definition) — описание допустимой структуры XML-документа. <https://en.wikipedia.org/wiki/Document_type_definition>
[^bom]: BOM (byte order mark) — невидимая метка в начале файла, указывающая кодировку/порядок байтов. <https://en.wikipedia.org/wiki/Byte_order_mark>
[^serializer]: Сериализатор — часть программы, записывающая данные из памяти в текст файла. <https://en.wikipedia.org/wiki/Serialization>
[^i3d]: i3d — XML-формат сцены GIANTS (3D-модель, узлы, трансформации). Файл `.i3d` тоже начинается с объявления XML.
