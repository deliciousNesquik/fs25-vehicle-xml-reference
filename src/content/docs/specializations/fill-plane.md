```xml
<fillUnit fillTypeCategories="bulk" capacity="12000">
    <fillPlane defaultFillType="wheat">
        <node node="fillPlaneNode" minMaxY="0.05 1.2"/>
    </fillPlane>
</fillUnit>
```

`<fillPlane>` — **дешёвая визуализация** груза: один или несколько узлов, которые движок двигает,
поворачивает и масштабирует по проценту заполнения ёмкости. Никакой физики формы: плоскость просто
поднимается снизу вверх. Реалистичная куча с откосом и деформацией — это
[`<fillVolume>`](fill-volume.md).

Блок живёт **внутри** ёмкости [`<fillUnit>`](fill-unit.md), поэтому отдельного `fillUnitIndex` ему
не нужно — он всегда показывает уровень своей ёмкости.

> Расположение: блок `vehicle.fillUnit…fillUnit(?).fillPlane`. Раздел справочника — Specializations.
>
> Источник схемы: `FillUnit.initSpecialization`, `FillUnit:loadFillPlane` и
> `FillUnit:updateFillUnitFillPlane` (FS25).

---

## 1. Полный путь и устаревшая форма

```text
vehicle.fillUnit.fillUnitConfigurations.fillUnitConfiguration(?).fillUnits.fillUnit(?).fillPlane
```

Устаревшее: `vehicle.fillPlanes.fillPlane` → путь внутри `<fillUnit>`. Отдельного корневого блока
`<fillPlanes>` в FS25 нет — движок специально проверяет старый путь и пишет предупреждение об
устаревшем элементе, а сам его не читает. Если перенесённая техника показывает пустой кузов при
наполненной ёмкости — почти всегда дело в этом.

Ещё две устаревшие записи: `fillPlane#fillType` → материал теперь назначается динамически;
`node#index` → `#node`.

---

## 2. Атрибуты

`<fillPlane>`:

| Путь | Тип | По умолчанию | Описание |
|---|---|---|---|
| `#defaultFillType` | STRING[^string] | первый поддерживаемый тип ёмкости | Тип груза, чья текстура берётся по умолчанию. Неизвестное имя — предупреждение, блок не загрузится. |

`<node(?)>` — сама плоскость, элемент индексируемый:

| Путь | Тип | По умолчанию | Описание |
|---|---|---|---|
| `#node` | NODE[^node] | — | Узел плоскости. Обязателен. |
| `#minMaxY` | VEC2 | текущий Y узла | Нижняя и верхняя высота: положение при пустой и полной ёмкости. |
| `#alwaysVisible` | BOOL[^bool] | `false` | Показывать узел даже при нулевом уровне. |

`<key(?)>` — ключ анимации внутри `<node>`, если движения по одной оси мало:

| Путь | Тип | По умолчанию | Описание |
|---|---|---|---|
| `#time` | FLOAT[^float] | — | Момент ключа: доля заполнения `0…1`. Обязателен, иначе разбор ключей прерывается. |
| `#translation` | VEC3 | — | Положение узла в этом ключе. |
| `#y` | FLOAT | — | Только высота, если остальные оси не меняются. |
| `#rotation` | VEC3 | — | Поворот в этом ключе. |
| `#scale` | VEC3 | — | Масштаб в этом ключе. |

---

## 3. Как это работает

При загрузке для каждого `<node>` строится кривая анимации:

- **есть `<key>`** — кривая собирается из ключей, время ключа = доля заполнения;
- **ключей нет** — кривая строится автоматически из двух точек по `#minMaxY`: нижняя высота при
  времени `0`, верхняя при `1`; X/Z и поворот берутся текущие из i3d, масштаб `1 1 1`.

Каждый кадр движок берёт процент заполнения ёмкости, вычисляет по кривой положение, поворот и
масштаб и применяет их к узлу. Видимость выставляется по правилу «уровень больше нуля **или**
`alwaysVisible`».

Материал плоскости назначается движком: берётся базовый материал `fillPlane`, к узлу подключаются
массивы текстур типов груза с террейна, а при смене типа груза обновляется параметр шейдера
`fillTypeId`. Поэтому материал, назначенный узлу в редакторе, значения не имеет — важна только
геометрия и положение. Если базовый материал не найден, в лог уходит ошибка
`Failed to assign material to fill plane`.

## 4. Примеры

Минимальный вариант — плоскость поднимается от 5 см до 1,2 м:

```xml
<fillPlane>
    <node node="fillPlaneNode" minMaxY="0.05 1.2"/>
</fillPlane>
```

Несколько плоскостей в одной ёмкости (отсеки кузова):

```xml
<fillPlane defaultFillType="barley">
    <node node="fillPlaneFront" minMaxY="0.1 0.9"/>
    <node node="fillPlaneRear"  minMaxY="0.1 0.9"/>
</fillPlane>
```

Движение с наклоном через ключи — плоскость не только поднимается, но и выравнивается:

```xml
<fillPlane>
    <node node="fillPlaneNode">
        <key time="0"   translation="0 0.05 0.2" rotation="4 0 0"/>
        <key time="0.5" translation="0 0.60 0.1" rotation="2 0 0"/>
        <key time="1"   translation="0 1.20 0"   rotation="0 0 0"/>
    </node>
</fillPlane>
```

## 5. Устройство в GIANTS Editor

- Плоскость — обычный шейп внутри кузова, чаще всего простой quad по размеру внутреннего сечения.
- Нижнее положение задаётся так, чтобы при пустой ёмкости плоскость была скрыта геометрией дна;
  верхнее — по краю бортов.
- Материал и текстуру ставить не нужно — движок назначает свои (раздел 3).
- Проверять удобно так: `alwaysVisible="true"` временно делает плоскость видимой и на пустой
  ёмкости, чтобы поймать положение по Y.
- Значения `#minMaxY` — **локальные** координаты узла относительно родителя, а не мировые.

---

## 6. Когда плоскость, а когда объём

| Признак | `<fillPlane>` | [`<fillVolume>`](fill-volume.md) |
|---|---|---|
| Форма груза | плоская поверхность | куча с углом откоса |
| Стоимость | почти нулевая | построение меша при загрузке |
| Деформация подвижными частями | нет | да, через `<deformNode>` |
| Требования к геометрии | любой узел | обязательно шейп |
| Наклон при движении/выгрузке | только вручную ключами | учитывается формой объёма |

Прицепы с сыпучим грузом и техника, где груз хорошо виден, используют объём; бункеры, баки и всё,
где видно лишь верх груза, спокойно обходятся плоскостью.

---

## 7. Типичные ошибки

- **Старый путь `<fillPlanes>` в корне** — в FS25 не читается (раздел 1).
- **Нет `#minMaxY` и нет ключей** — кривая строится из текущей высоты узла в обе точки, плоскость
  стоит на месте и выглядит «сломанной».
- **Ожидание своей текстуры** — материал назначается движком; `#fillType` у `<fillPlane>` устарел.
- **Плоскость видна на пустой ёмкости** — забыт `alwaysVisible="false"` (значение по умолчанию) или
  нижняя точка `minMaxY` выше дна кузова.
- **Ключ без `#time`** — разбор ключей прерывается на нём, остальные игнорируются.
- **Попытка сослаться на ёмкость** — `fillUnitIndex` у плоскости нет: она принадлежит той ёмкости,
  внутри которой записана.

---

## 8. Примечания

- Индексируемых плоскостей в одной ёмкости может быть сколько угодно — все двигаются по одному и
  тому же проценту заполнения.
- Плоскость и объём для одной ёмкости одновременно не нужны: они рисуют одно и то же.
- Поведение — по движку FS25 (`vehicles/specializations/FillUnit.lua`) и официальной схеме
  `vehicle.xsd`.
