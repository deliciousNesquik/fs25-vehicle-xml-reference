Точки крепления номерных знаков[^plate] на технике: узлы, куда игра подставляет готовые модели
номеров, их предпочтительный тип и допустимую область размещения.

Источник схемы: спецификация `LicensePlates` (`LicensePlates.lua`), `FS25`, ключ `vehicle.licensePlates`.

> Расположение: `<licensePlates>` — дочерний элемент корня `<vehicle>`. Раздел справочника — `specializations`.

---

## 1. Что это

`<licensePlates>` перечисляет узлы техники, к которым привязываются номерные знаки. Сами модели
номеров (геометрия, шрифт, размеры, цвета) хранятся не в технике, а в глобальной конфигурации
карты (загружается через `g_licensePlateManager`). Техника лишь указывает:
- к какому узлу (`node`) привязать номер;
- какой тип номера предпочесть (`preferedType`);
- к какой позиции относится узел (`position` — перёд/зад);
- сколько места доступно вокруг узла (`placementArea`), чтобы номер автоматически уменьшился под него;
- показывать ли рамку (`frame`).

При загрузке для каждого узла игра берёт из глобальной конфигурации клон подходящего номера,
привязывает его к `node`, обнуляет смещение и поворот и масштабирует под `placementArea`.

Пример с передним и задним номером:

```xml
<licensePlates>
    <licensePlate node="licensePlateFront" position="FRONT" preferedType="SQUARISH"/>
    <licensePlate node="licensePlateBack"  position="BACK"  preferedType="ELONGATED"/>
</licensePlates>
```

|---|---|---|---|
| `defaultPlacement` | STRING | — | Правило размещения по умолчанию (см. таблицу значений ниже). |

---

## 3. Атрибуты `<licensePlate>`

Регистрируются в `LicensePlates.registerXMLPaths`.

| Атрибут | Тип | По умолчанию | Описание |
|---|---|---|---|
| `node` | NODE_INDEX[^node] | — (обязателен) | Узел, к которому привязывается модель номера. Без узла запись пропускается. |
| `preferedType` | STRING | `ELONGATED` | Предпочтительный тип (форма) номера. Если тип неизвестен, запись пропускается. |
| `position` | STRING | `ANY` | Позиция узла на технике (перёд/зад). |
| `placementArea` | STRING | `1 1 1 1` | Доступное место вокруг узла: четыре числа через пробел `top right bottom left` (метры); `-` — без ограничения по стороне. |
| `frame` | BOOL | `true` | Показывать номер с рамкой (`true`) или без неё (`false`). |

> Атрибут пишется `preferedType` — с одной буквой `r`. Написание `preferredType` не распознаётся.

---

## 4. Значения `position` (enum `PLATE_POSITION`)

| Значение | Описание |
|---|---|
| `ANY` | Позиция не задана; значение по умолчанию. |
| `FRONT` | Передний номер. |
| `BACK` | Задний номер. |
| `NONE` | Номер не размещается. |

> Полная таблица `PLATE_POSITION` в открытом зеркале исходников не опубликована. Перечислены
> значения, которые явно используются в коде; наличие других (например `LEFT`/`RIGHT`) не подтверждено.
> Комментарий схемы указывает только `FRONT` и `BACK`, значение по умолчанию — `ANY`.

---

## 5. Значения `preferedType` (enum `PLATE_TYPE`)

| Значение | Описание |
|---|---|
| `ELONGATED` | Вытянутый (длинный) номер; значение по умолчанию. |
| `SQUARISH` | Квадратный (укороченный) номер. |

> Полная таблица `PLATE_TYPE` в открытом зеркале исходников не опубликована. Подтверждены значения
> `ELONGATED` и `SQUARISH` (из схемы и значения по умолчанию). Тип — это предпочтение: игра выбирает
> из глобальной конфигурации карты последний номер с совпадающим типом, а при отсутствии совпадения
> берёт первый доступный.

---

## 6. Значения `defaultPlacement` (enum `PLACEMENT_OPTION`)

| Значение | Описание |
|---|---|
| `BOTH` | Номера спереди и сзади. |
| `BACK_ONLY` | Только задний номер; узлы с `position="FRONT"` не заполняются. |
| `NONE` | Номера не размещаются. |

> Полная таблица `PLACEMENT_OPTION` в открытом зеркале исходников не опубликована. Перечислены
> значения, используемые в коде. Значение сопоставляется по верхнему регистру (`name:upper()`).

---

## 7. Как работает `placementArea`

`placementArea` задаёт габарит доступного места вокруг узла в порядке `top right bottom left`
(верх, право, низ, лево), в метрах. По этим числам вычисляется допустимая ширина и высота номера,
затем модель номера **уменьшается** (коэффициент масштаба ограничен диапазоном `0..1`), чтобы
вписаться. Символ `-` на стороне снимает ограничение по этой стороне.

```xml
<!-- Номер вписывается в 0.2 м сверху/снизу и 0.25 м слева/справа -->
<licensePlate node="licensePlateBack" position="BACK" placementArea="0.2 0.25 0.2 0.25"/>

<!-- Ограничение только по высоте, ширина без ограничения -->
<licensePlate node="licensePlateBack" position="BACK" placementArea="0.15 - 0.15 -"/>
```

---

## 8. Примеры

Один задний номер без рамки:

```xml
<licensePlates>
    <licensePlate node="licensePlateBack" position="BACK" preferedType="ELONGATED" frame="false"/>
</licensePlates>
```

Передний и задний номера разной формы:

```xml
<licensePlates>
    <licensePlate node="licensePlateFront" position="FRONT" preferedType="SQUARISH"/>
    <licensePlate node="licensePlateBack"  position="BACK"  preferedType="ELONGATED"/>
</licensePlates>
```

Только задний номер на уровне всей техники:

```xml
<licensePlates defaultPlacement="BACK_ONLY">
    <licensePlate node="licensePlateFront" position="FRONT"/>
    <licensePlate node="licensePlateBack"  position="BACK"/>
</licensePlates>
```

## 9. Устройство узлов в GIANTS Editor

- `node` — пустая трансформгруппа[^tg] в точке крепления номера. Модель номера привязывается к узлу
  с обнулённым поворотом и наследует его ориентацию: плоскость номера лежит в осях узла X (ширина) и
  Y (высота), нормаль (лицевая сторона) — вдоль оси Z. Узел ориентируется лицевой стороной наружу от
  корпуса. Смещение при подгонке под `placementArea` идёт только по X и Y.
- Собственную геометрию номера в модель техники добавлять не требуется — она берётся из
  глобальной конфигурации карты.
- Имена узлов прописываются в `<i3dMappings>` (см. раздел i3dMappings).

---

## 10. Типичные ошибки

- Написание `preferredType` (две `r`) — атрибут не распознаётся, применяется тип по умолчанию.
- Узел `node` отсутствует или имя не прописано в `<i3dMappings>` — запись пропускается, номер не появляется.
- `placementArea` меньше реального места — номер уменьшается сильнее ожидаемого.
- `defaultPlacement="BACK_ONLY"` при наличии переднего узла — передний номер не отображается, это ожидаемое поведение.

---

## 11. Примечания

- Геометрия, шрифт, размеры и цвета номеров задаются глобальной конфигурацией карты, а не техникой.
- `preferedType` — предпочтение, а не жёсткое требование: при отсутствии совпадающего типа
  подставляется первый доступный номер.
- Атрибуты сохранённой игры (`variation`, `characters`, `colorIndex`, `placementIndex`) относятся
  к файлу сейва, а не к XML техники.
