```text
vehicle.cultivator                     блок
.sounds.work(?)                        индексируемый под-элемент
#useDeepMode                           атрибут
.directionNode#node                    атрибут под-элемента
```

Все страницы устроены одинаково, и почти все таблицы записывают пути в одной нотации — она взята
из движка (так пути регистрируются в коде игры). Эта страница объясняет нотацию, типы значений и
порядок разделов, чтобы дальше читать таблицы без пояснений.

---

## 1. Нотация путей

| Запись | Что означает | Пример |
|---|---|---|
| `имя` | элемент (блок) | `vehicle.cultivator` — блок `<cultivator>` внутри корня `<vehicle>` |
| `#имя` | **атрибут** элемента | `#useDeepMode` → `<cultivator useDeepMode="false">` |
| `.имя` | **дочерний** элемент | `.directionNode` → `<directionNode>` внутри блока |
| `.имя#атрибут` | атрибут дочернего элемента | `.directionNode#node` → `<directionNode node="..."/>` |
| `(?)` | элемент **индексируемый**: повторяется списком | `.sounds.work(?)` → `<work>`, `<work(1)>`, … |
| `<имя>` | имя тега в тексте | `<components>`, `<fillTypes>` |

Точка — это шаг вниз по дереву, решётка — переход к атрибуту. Путь из таблицы всегда можно
развернуть в XML: `vehicle.cultivator.sounds.work#template` — это

```xml
<vehicle>
    <cultivator>
        <sounds>
            <work template="DEFAULT_CULTIVATOR_WORK"/>
        </sounds>
    </cultivator>
</vehicle>
```

Индекс в имени (`work(1)`) — способ движка адресовать второй и последующие элементы списка; в самом
XML индексы не пишут, элементы просто идут друг за другом.

## 2. Типы значений

В колонке «Тип» стоит тип, которого движок ждёт от значения атрибута:

| Тип | Значение | Пример |
|---|---|---|
| BOOL[^bool] | `true` / `false` | `useDeepMode="false"` |
| INT[^int] | целое число | `descVersion="98"` |
| FLOAT[^float] | число с плавающей точкой | `volumeScale="1.2"` |
| STRING[^string] | строка: имя, путь, ключ локализации | `filename="scripts/script.lua"` |
| VEC3 / VECn | несколько чисел через пробел | `linkNodeOffset="0 0.15 0"` |
| NODE[^node] | ссылка на узел i3d[^i3d] | `linkNode="soundNode"` |

**NODE** — самый частый источник ошибок: значением может быть либо имя из
[`<i3dMappings>`](../base/i3d-mappings.md), либо путь по дереву сцены в форме
`компонент>ребёнок|ребёнок`. Если узел не резолвится, движок обычно молча откатывается к корню
техники — визуально это выглядит как «блок не работает».

Строковые значения вида `$l10n_<ключ>` — это ключи локализации; как они попадают в мод, описано в
[`<l10n>`](../mod-desc/l10n.md).

## 3. Колонка «По умолчанию»

- Конкретное значение (`true`, `5`, `1`) — движок подставит его, если атрибут не указан.
- `—` — значения по умолчанию нет: либо атрибут обязателен, либо поведение без него не определено.
- Словесное значение (`из шаблона`, `components[1].node`, `реальное число нод в i3d`) — движок
  берёт величину из другого места, а не из константы.

Обязательность отмечается либо отдельной колонкой «Обязателен», либо словами в описании — там, где
это важно (например у `<specialization>` обязательны все три атрибута).

---

## 4. Из чего состоит страница

1. **Канонический XML** — сразу под заголовком, до объяснений: минимальная рабочая форма блока.
2. **Абзац назначения** и строка `> Расположение:` — где именно в файле лежит блок и к какому
   разделу справочника относится.
3. **Нумерованные разделы** — что это, атрибуты, под-элементы, примеры, устройство в GIANTS
   Editor[^giantseditor].
4. **Типичные ошибки** — симптом, причина, решение.
5. **Глоссарий** — сноски с определениями типов и терминов, использованных на странице.

Каждая страница самодостаточна: таблицы, примеры и глоссарий не требуют читать соседние страницы.
Где связь важна (например `<cultivator>` работает только вместе с рабочими зонами), она названа
явно и оформлена ссылкой.

---

## 5. Устаревшие формы

Строка вида

> Устаревшее: `directionNode#index` → `#node`

означает: старая запись ещё читается движком, но в новых модах использовать нужно правую форму.
Справочник описывает только FS25 — сравнений с предыдущими версиями игры в тексте нет.

---

## 6. Если не нашли блок в дереве

- [Указатель тегов A→Z](tag-index.md) — плоский список документированных элементов; работает, когда
  имя тега известно, а раздел — нет.
- Поиск (кнопка сверху или <kbd>Ctrl</kbd>+<kbd>K</kbd>) индексирует **весь текст**, включая
  таблицы атрибутов и примеры XML: искать можно прямо по `useDeepMode` или `DEFAULT_CULTIVATOR_WORK`.
- Раздел [Рецепты](../recipes/localization.md) — вход по задаче, а не по имени тега.
