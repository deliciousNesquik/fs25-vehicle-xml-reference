```xml
<title>
    <en>Disc Harrow Pack</en>
    <ru>Пак дисковых лущильников</ru>
</title>

<l10n filenamePrefix="localization/l10n"/>
```

Рецепт собирает в один порядок действий то, что в справочнике описано по элементам: как сделать
многоязычными витрину мода (название, описание) и его собственные строки (кнопки, названия
конфигураций, тексты помощи).

---

## 1. Что вообще локализуется

| Что видит игрок | Где задаётся | Способ |
|---|---|---|
| Название мода в списке | [`<title>`](../mod-desc/title.md) | языковые дочерние теги |
| Описание мода | [`<description>`](../mod-desc/description.md) | языковые дочерние теги, обычно в [CDATA](../concepts/cdata.md) |
| Строки самого мода (конфигурации, действия, GUI) | [`<l10n>`](../mod-desc/l10n.md) | ключи + `$l10n_<ключ>` |
| Название и описание в магазине | `<storeData>` файла предмета (см. [`<storeItems>`](../mod-desc/store-items.md)) | ключи `$l10n_` |
| Страницы помощи | [`<helpLines>`](../mod-desc/help-lines.md) | текст или ключи `$l10n_` |
| Названия действий ввода | [`<actions>`](../mod-desc/actions.md) | ключ `input_<name>` |

Первые две строки таблицы — отдельный механизм: язык задаётся **тегом внутри элемента**. Всё
остальное работает через ключи локализации.

---

## 2. Шаг 1 — название и описание

Дочерние теги `<title>` и `<description>` — это коды языков из закрытого набора (ровно 27 кодов,
полная таблица — на странице [`<title>`](../mod-desc/title.md)). Произвольные теги схема не примет.

```xml
<title>
    <en>Disc Harrow Pack</en>
    <ru>Пак дисковых лущильников</ru>
    <de>Scheibenegge-Paket</de>
</title>

<description>
    <en><![CDATA[Disc harrows for shallow tillage & seedbed.]]></en>
    <ru><![CDATA[Дисковые лущильники для мелкой обработки и семенного ложа.]]></ru>
</description>
```

`<en>` схемой не требуется, но фактически обязателен: именно он служит фолбэком для всех языков,
для которых своего тега нет. Мод без `<en>` у части игроков окажется без названия.

[CDATA](../concepts/cdata.md) в описании нужен, если в тексте есть `&`, `<`, `>` или многострочная
разметка — иначе XML не разберётся.

---

## 3. Шаг 2 — строки мода: внешние файлы или инлайн

Два **альтернативных** способа наполнить `<l10n>`. Смешивать их не следует: правило приоритета
движком не определено.

**Внешние файлы** — когда строк много или перевод отдают команде:

```xml
<l10n filenamePrefix="localization/l10n"/>
<!-- файлы: localization/l10n_en.xml, localization/l10n_ru.xml, … -->
```

Базовое имя произвольно, фиксирован только суффикс `_<код>.xml`. Каждый файл — один язык:

```xml
<!-- localization/l10n_ru.xml -->
<l10n>
    <texts>
        <text name="option_wheels" text="Выбор опорных колёс"/>
    </texts>
</l10n>
```

**Инлайн** — когда строк немного:

```xml
<l10n>
    <text name="option_wheels">
        <en>Selection of support wheels</en>
        <ru>Выбор опорных колёс</ru>
    </text>
</l10n>
```

Разница только в форме: во внешнем файле язык закодирован в имени файла, а значение лежит в
атрибуте `text=`; инлайн задаёт языки дочерними тегами внутри одного `<text name=>`. Подробности,
включая вторую (документированную, но не встречающуюся в живых модах) форму внешнего файла — на
странице [`<l10n>`](../mod-desc/l10n.md).

---

## 4. Шаг 3 — использовать ключ

В XML — литерал `$l10n_<ключ>` в текстовом атрибуте:

```xml
<designConfiguration name="$l10n_option_wheels" price="450"/>
```

В Lua — `g_i18n:getText("option_wheels")`.

Подстановка `$l10n_` работает в большинстве текстовых полей, но **не во всех** (известный пример —
`sellingStation#stationName`). Каждое новое место стоит проверять в игре, а не считать
гарантированным.

---

## 5. Фолбэк и область видимости

- Для текущего языка нет строки → берётся `en`. Нет и `en` → в интерфейсе останется литерал
  `$l10n_<ключ>`, а в лог попадёт `missing <ключ> in l10n_<язык>.xml`.
- Тексты мода **приватны**: их видит только сам мод. Код базовой игры их не читает — это защита от
  конфликта ключей между модами. Обход для базового контекста описан в разделе 6 страницы
  [`<l10n>`](../mod-desc/l10n.md).
- Вторичный фолбэк на `de` после `en` упоминается сообществом, но GIANTS не подтверждён —
  полагаться стоит только на `en`.

---

## 6. Проверка

1. Запустить игру с языком, для которого перевода **нет** — должен показаться английский текст,
   а не пустая строка и не `$l10n_…`.
2. Посмотреть лог на `missing <ключ>`: он ловит опечатки в именах ключей.
3. Проверить имена файлов: строго `_<код>.xml` (не `.en.xml`, не `_english.xml`).

---

## 7. Типичные ошибки

- **Нет `<en>` / `l10n_en.xml`** — для языков без своего перевода текста не будет вовсе.
- **Смешаны `filenamePrefix` и инлайн-`<text>`** — приоритет не определён, результат непредсказуем.
- **Неверный суффикс файла** — движок его просто не найдёт, без явной ошибки.
- **Произвольный языковой тег** (`<eng>`, `<rus>`) — набор кодов закрытый, тег не будет принят.
- **Ожидание, что `$l10n_` работает в любом атрибуте** — есть места, где подстановки нет.
